# 모델과 대수별 운영 판단

## 공통 입력과 분할

같은 origin의 동일 입력/정답을 사용합니다. lag 1/2/3/24/168시간 중 history 이하의 값과
history 끝점, 관측 여부, 측정 시작 재고와 측정 여부, 시간/요일, 위치를 사용합니다.
과거 누락은 0과 누락 표시를 함께 입력하고, 정답 누락은 손실·평가에서 제외합니다.
미래 실측 재고와 예측 대상 구간의 거래는 입력에 들어가지 않습니다.

거리 유사도와 학습 기간 시간별 거래 패턴의 cosine 유사도를 같은 비율로 결합합니다.
상위 k 이웃을 대칭화하고 자기 루프·행 정규화합니다. 64개 이상은 sparse 연산을 씁니다.
OD·잠재 수요 정답을 가정하지 않습니다. 일반 GCN에는 별도 시간 합성곱이 없고 lag가 시간을 반영합니다.

## Flow Matching

일반 GCN과 같은 사전학습 인코더·평균을 복사/고정합니다. 정답 y에 U(0,1)을 더해
log1p로 바꾼 뒤 기본 평균 log1p에 대한 잔차를 구합니다. Gaussian 잡음 z에서 정답
잔차 r까지 선형 보간하고 속도 r-z를 회귀합니다. 속도 모델은 context·현재 잔차·
생성 시간 tau를 받아 공간 전파합니다. tau는 실제 예측 시간 h와 다릅니다.
정답 누락 좌표는 잡음 prior에 남기고 손실에서 제외합니다.

독립 표본 결합 CFM이며 minibatch OT를 풀지 않습니다. 추론은 여러 잡음 시작점에서
midpoint ODE로 적분하고 baseline을 더한 뒤 floor(max(expm1(log_count),0))로 정수화합니다.
수치 안정성을 위해 log_count를 [-12,8]로 제한합니다. 이것은 물리적 수요/용량 상한이 아닙니다.

GCN/XGBoost의 확률은 예측 평균에 대한 독립 Poisson 시나리오입니다. 이 비교만으로
모든 확률 기준선보다 우수하다고 주장하지 않습니다. 다음 확장으로 음이항/보정을 비교할 수 있습니다.
검증 손실이 가장 좋은 가중치를 다시 불러와 저장하고, 저장 모델을 재로딩해 평가합니다.
새 실행은 검증 건수 MAE·재고 MAE·품절 Brier·0대 회복 Brier를 일반 GCN 대비 정규화해
동등 가중 평균이 가장 작은 모델을 선택합니다. 공통 미평가 지표는 제외합니다.
이전 실행은 기존 Brier/CRPS 선택 기록을 유지하며 evaluate로 다시 평가할 수 있습니다.

## 검증 자료에서의 보정

`gcn_flow_calibrated`는 Flow의 시간·채널별 평균 건수 비율 보정 후보와 GCN/Flow
시나리오 혼합을 비교합니다. 정수화한 시나리오를 사용하고 현재 0대/재고 보유 그룹을
따로 조정합니다. 각 그룹에서 건수·재고 MAE가 GCN의 1.01배 이내인 후보 중 사건 Brier를
최소화합니다. 0대 그룹의 사건은 자연 회복, 재고 보유 그룹은 품절입니다.
GCN만 쓰는 후보가 항상 포함됩니다. 검사 가능한 재고가 없으면 건수 오차만 조정합니다.
보정 비율과 비중은 검증 자료만 사용하며 시험 정답·요청 수를 읽어 조정하지 않습니다.
이는 isotonic/Platt 확률 보정이나 점수 향상 보장이 아닙니다. 단일 검증 자료로 보정과
모델 선택을 하므로 독립 시험과 여러 시드 검증이 필요합니다.

## 모델 확대와 메모리 관리

`base`/`medium`의 폭은 48/96이며 GCN 2층, Flow 1블록입니다.
`large`는 폭 256·GCN 4층·Flow 4블록, `rtx3080`은 폭 512·GCN 4층·Flow 6블록입니다.
추가 Flow 블록은 그래프 전파, 생성 시간에 따른 조정, 확장 FFN과 잔차 연결을 사용합니다.
학습된 평균 GCN은 Flow 학습 중 고정하고 dropout도 비활성화합니다.

CUDA에서는 혼합 정밀도로 밀집 연산을 수행하고 sparse 그래프 전파·손실·ODE 상태는
float32로 유지합니다. 배치 누적은 관측 정답 수로 가중해 누락 비율에 따른 편향을 막습니다.
검증 손실 기준 조기 종료와 최적 가중치 복원을 적용합니다. 시나리오 생성은 입력 문맥을
한 번 계산한 뒤 작은 묶음으로 처리하고 결과는 CPU로 옮깁니다. 실제 VRAM 사용량은
대여소·이력·예측 길이에 따라 달라지며 GPU가 없는 환경에서는 CUDA 검사가 건너뛰어집니다.
이전 기본형/medium 저장 모델도 불러올 수 있지만 층과 폭을 확대하려면 재학습해야 합니다.
실행·오류 대응·결과 공유 명령은 루트 `run.md`에 모읍니다.

## 재고 계산

시간마다 먼저 served=min(I,rentals)를 빼고 다음에 returns를 더합니다.
capacity가 확인됐으면 빈 공간만큼만 반납을 수용하고 나머지는 반납 수용 실패로 집계합니다.
재고는 비음수 정수이며 용량을 넘지 않습니다. 대여 후 반납이라는 보수적 시간 순서 가정은
실제 분 단위 사건과 다를 수 있습니다.

관측 거래는 공급 부족 때 잠재 수요보다 작을 수 있습니다. 여기의 미처리 대여는 생성한
관측 거래 시나리오를 재고와 대조한 서비스 실패 **대리 지표**입니다. 미충족 수요 정답이 아닙니다.
예측 대여/반납은 도시 전체 OD·이동시간을 보존하는 물리 모형이 아니며 운행 중 자전거,
외부 반납, 반납 실패 재시도까지 모두 추적한다고 해석하지 않습니다.

현재 재고>0인 곳의 미래 정시 품절과 현재 0대인 곳의 회복을 따로 평가합니다.
두 클래스가 있을 때만 AUC를 계산합니다. 실측 재고 누락은 평가하지 않습니다.

## 목표와 이동

각 시나리오에서 시각별 누적 대여에서 직전까지의 누적 반납을 뺀 최대값을 필요 시작
재고로 봅니다. 그 값의 quantile(기본 0.9)을 목표로 삼고 확인된 capacity로 제한합니다.
용량이 있을 때 이 목표만으로 서비스 수준을 보장하지 않으며 시뮬레이션에서 실패를 다시 계산합니다.

공급처는 목표보다 많은 곳, 수요처는 목표보다 적은 곳으로 한정합니다. 한 대를 옮겨
줄어드는 수요처 실패보다 공급처의 실패 증가가 작을 때만 이동합니다. 실패에는 대여
미충족과 반납 수용 실패를 함께 포함합니다. 직선거리로 가중한 탐욕 선택이므로 전역
최적해를 주장하지 않습니다. 총 이동 대수 예산·최대 거리를 강제합니다.

출발/도착이 같은 선택을 묶고 적재 한도에 맞게 직접 이동 배치로 나눕니다.
전후 자전거 재고 합은 같습니다. 이동은 예측 시작 직전에 끝난다고 가정합니다.
직선거리는 실제 도로거리/소요시간이 아니고 depot·다중 정차 VRP는 계산하지 않습니다.

도보 대체 이용, 잠재 수요 검열 모형, 고장 판별, 실시간 API 수집은 현재 공식 경로에
포함하지 않았습니다. 확인 가능한 자료 없이 추정치를 사실로 만들지 않기 위한 범위입니다.

## 독립 재배치 재생 평가

시험 시점의 시작 재고와 예측 시나리오만으로 이동 계획을 고정하고, 그 후 실제 관측
대여·반납을 넣어 이동 없음·가까운 잉여 대여소의 0대 우선 보충·순이익 추천을 비교합니다.
평가에는 같은 예산·거리·서비스 목표를 사용합니다. 대여 실패·반납 실패·0대 대여소 시간·
회복·이동 대수를 기록하며 악화된 결과도 그대로 저장합니다. 완전한 도시 관측이 없으면
미평가로 표시합니다. 시점은 독립 실행이고 차량의 하루 연속 운행 성과가 아닙니다.

관측 대여는 공급에 의해 검열되므로 해당 재생은 잠재 수요 개선의 정답이 아닙니다.
새 합성 생성기의 requested_rentals는 평가 전용으로 보관하며, 이 요청 수를 이용한 별도
재생도 제공합니다. 요청 수는 특징·학습 정답·보정·계획에 들어가지 않습니다. 사용자 자료의
요청 수는 검증되지 않은 제공 증거로 표시합니다. 요청 재생도 반납량을 고정하므로
이동에 따른 후속 OD·반납 변화까지 계산하는 정책 실험은 아닙니다.
