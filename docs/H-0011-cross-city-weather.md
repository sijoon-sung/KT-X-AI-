# H-0011: 실제 대여소 전이 표현과 날씨를 쓰는 예측 연구

## 가설

서울에서 학습한 64차원 대여소 프로필 표현과 대전의 과거 기상을 넣은 큰 GCN이
큰 달력·큰 기상·무작위 표현 세 대조군 모두보다 다계절 기록 건수 deviance를 1% 넘게 줄인다.
3일/7일 블록 구간의 하한도 모두 1%를 넘어야 지지한다. 공식 재고 정확도 판정은 아니다.

계획 해시 `fd2d8647350c51a9702439569ebbdebe062d01db6ac8f01e475d45b9b5afdb01`.
[Draft PR #18](https://github.com/sijoon-sung/KT-X-AI-/pull/18)에 학습 전에 게시했다.
주 구현 커밋 `3664fbd48daf86fa22889c6dff550c9bc704f93e`도 실행 전에 게시했다.

## 실험

실행 중. 원본·설계·예산·시간 분할은 [동결 기록](../research/hypotheses/H-0011.json)을 따른다.
작은/큰 달력, 큰 기상, 큰 기상+무작위 인코더, 큰 기상+서울 사전학습 인코더의 다섯 후보를 비교한다.

| 분할 | 학습 종료(미포함) | 내부 선택 | 과거 건수 보조시험 |
|---|---|---|---|
| spring | 2025-03-01 | 2025년3월 | 2025년4~5월 |
| summer | 2025-07-01 | 2025년7월 | 2025년8~9월 |
| winter | 2026-02-01 | 2026년2월 | 2026년3월 |

모든 분할의 타슈 학습 시작은2024-08-01. 서울은2024년이며 양 도시 대여소ID를 서로 대응시키지 않는다.
각 분할의 학습만으로 코호트·OD·프로필·기상 표준화를 다시 만든다.
겨울 이후 거래 정답과 미래 재고 정답을 구분한다. 2025-12는 자료 불일치로 결측이다.

456차원 주간/월별/관측마스크 프로필을 서울에서 인코더로 압축한다. 출퇴근형 등의 실제 의미 라벨을 학습한 것은 아니다.
같은 초기 무작위 인코더와 비교하므로 입력 차원 증가의 효과를 구분할 수 있다.
포아송은 기록 건수의 평균 학습 손실이다. 재고의 분포 가정이나 Flow Matching 우위까지 검증하지 않는다.

시간별 GHCNh의 기온·풍속·습도·3시간 강수와 결측·나이·trace를 사용한다.
예측 시작1시간 이전 보고/최대4시간 나이, 변수별 QC와 물리 범위를 적용한다.
미래 실측 날씨·타슈 재고 API는 입력하지 않는다. 사후 수정된 기상 아카이브의 실시간 도착은 검증하지 못했다.

로컬 RTX4060 Laptop8GB·Python3.12.14·torch2.7.1+cu128·numpy1.26.4·pandas2.2.3.
CPU4thread/GPU사용상한55%, 각후보2seed·12epoch+0, 각epoch262144노출.
source사전학습100epoch는 추가 연산으로 따로 기록한다. 원본은 청크 처리한다.

합성 검사7개가 통과했다. 시각/월경계, 프로필 결측·규모 불변성, QC·trace,
기상 지연/미래 비의존, 학습 전용 표준화, 미래OD/프로필 비의존, 최적화·가중치 저장/복원을 검사했다.
주 구현의 원격 Research protocol #75도 성공했다. 형식 검사는 모델 우위의 증거가 아니다.
