# 타슈 권역별 재배치 시나리오

## 90초 IR 시연

[무음 영상](../assets/demo/tashu-ir-gpt-demo.mp4) · [발표자 메모](tashu-ir-gpt-cues.md) · [계산과 GPT 답변 기록](../assets/demo/ir-gpt-capture.json)

대전 전체의 대여소 이용 연결에서 동네 지도로 들어간다. 태평동 쌍용예가의 같은 관측에서 생성한 대여·반납 표본 세 가지를 보여준다. 화면의 화살표는 대여소에 들어오고 나가는 수량을 나타낸다. 각 행은 저장된 짝에서 중복을 제외한 예시이며 행 순서는 시간 순서와 무관하다. 이어서 문화동 센트럴파크를 저녁 배차의 부족 후보로 확인한다. `경로 계산`을 누르면 dislab이 태평·문화, 둔산, 대전역의 경로를 계산한다. GPT에게 수거·배치 장소와 수량을 묻고, 세 차량의 작업표를 보여준다.

촬영에서는 로그인된 OpenAI Codex CLI의 `gpt-6.1-sol`을 사용했다. GPT에 전달하는 내용은 선택한 작업표와 질문이다. 계산 서버가 답변의 대여소 이름·순서·수량·작업을 대조한 뒤 화면에 표시한다. GPT 응답 대기 구간을 편집했다. 각 권역에 차량이 한 대씩 출발한다는 조건으로 2026년 11월 10일 저녁 관측을 재생했다. [Codex CLI 실행 방법](https://developers.openai.com/codex/noninteractive)

영상 편집에는 촬영 PNG, 저장된 예측, 세 권역 경로와 OSM 도로 지도를 사용한다. `export_comparison_map.py --case taepyeong-2050 --case dunsan-2050 --case station-2050`으로 `ir-fleet-map.json`을 시나리오 폴더에 저장한다. dislab에서 `tools/render_ir_product_demo.py`에 `--local`, `--scenarios`, `--shots`, `--out`, `--ffmpeg` 경로를 전달한다.

## 시연 실행

1. dislab에 이 브랜치와 Python 실행 환경을 준비한다. 원격 설정 JSON에 기존 관측 폴더 `stream`, `design/dispatch-scenarios.json`의 경로 `spec`, OSRM 도로 캐시 `roads`를 지정한다.
2. 로컬 설정 JSON에 SSH 별칭 `ssh_host`, dislab Python 경로 `remote_python`, dislab의 `tools/product_live_worker.py` 경로 `remote_worker`, 원격 설정 경로 `worker_config`, 로컬 시연 임시 폴더 `relay_workspace`를 넣는다. GPT 시연은 `"provider": "openai-codex"`를 넣고 공식 CLI의 `codex login status`로 로그인 상태를 확인한다. Antigravity 시연은 `provider`를 생략하거나 `antigravity`를 넣고 로그인된 CLI 경로 `agy`를 지정한다.
3. 아래 명령으로 로컬 서버를 열고 브라우저에서 `경로 계산 → 태평·문화 → 작업 순서 질문`을 실행한다. `/health`에서는 서버와 선택한 답변 연결 설정을 확인한다. 원격 경로 계산과 모델 응답은 브라우저에서 확인한다.

```powershell
python tools/serve_product_live.py --config LOCAL_CONFIG --capture-log CAPTURE_LOG --port 8778
Invoke-RestMethod http://127.0.0.1:8778/health
```

브라우저 주소는 `http://127.0.0.1:8778/`이다. 즉시 영상에 쓸 때는 [조회용 제품 화면](../assets/demo/dispatch-product-demo.html)을 다운로드해 열면 기존 작업표와 경로를 볼 수 있다.

## 경로 계산과 답변 시연

무음 영상은 38초다. 대전 전체에서 태평·문화권으로 확대해 Flow Matching이 만든 흐름을 잠깐 보여준다. `경로 계산`을 누르면 보관된 관측을 입력으로 dislab에서 세 권역의 실제 도로 경로를 계산한다. 태평·문화 작업표에서 “어디서 몇 대를 싣고, 어디에 내려놓나요?”를 보낸 뒤 모델의 답변을 표시한다. 마지막 화면에는 세 권역의 경로와 작업표가 나온다. 촬영에서 답변까지 걸린 시간은 약 13초이며 영상에서는 대기 구간을 줄였다. 발표 영상에는 지도, 작업 장소와 순서, 묶음 수량을 표시한다. 거리와 예상 시간, 예측 확률 등 발표자가 설명하는 세부 수치는 아래 기록과 시나리오 뷰어에서 확인할 수 있다.

## 창업 발표용 제품 시연

**배차 담당자가 여러 권역의 부족 대여소를 보고, 차량마다 수거·배치 작업표를 확인한다.** 구매 검토 대상은 공공자전거 운영기관이다. 같은 저녁 관측에서 태평·문화, 둔산, 대전역 권역의 경로를 한 화면에 띄운다. 차량이 각 권역에서 출발하는 조건으로 계산한 작업 계획이다. 담당자가 도시 전체의 작업을 살펴보고 필요한 경로를 골라 확인하는 모습을 보여준다.

### 촬영에 사용할 화면

발표용 HTML을 브라우저에서 연다. `전체 작업`, `태평·문화`, `출발 전 확인`, `전체 작업` 순서로 미리 계산된 계획을 조회할 수 있다. 총수량·거리·마감 시각·예측 확률·검사 건수는 발표자가 설명할 때만 언급한다. 권역별 작업량은 어느 차에 어떤 작업을 맡길지 보여주는 데 사용한다.

Flow Matching은 관측에서 부족 후보가 나오기까지의 짧은 지도 전환에 사용한다. 빈자리 제한과 짧은 복귀 마감은 현장 제약이 바뀔 때의 대응을 묻는 질의응답에 사용한다. 생성 단계와 분포 비교는 기술 질의응답 자료로 둔다.

창업 발표를 마칠 때는 **한 권역에서 운영자와 시범 적용**을 제안한다. 의사결정에 걸린 시간, 차량 작업 시간, 작업 후 대여소의 재고 부족을 기록해 도입 가치를 확인한다.

기존 영상의 단일 왕복을 일괄 경로 계산과 권역별 비교로 확장했다. 차량 출발 위치, 복귀 마감, 배치할 빈자리가 달라질 때 수량과 경로가 어떻게 바뀌는지 볼 수 있다. 대전 전체 화면에는 모델이 지원하는 대여소 1,294곳과 과거 대여소 연결 일부를 표시하고 태평·문화권으로 확대한다. 가까운 지도에서는 고정 Flow Matching의 실제 보정값과 대여·반납 표본을 보여 준다. [지도 출처](https://www.openstreetmap.org/relation/2349984)

## 경로 계산 프로그램

`tools/scenario_dispatch.py`는 저장된 H13 예측과 [시나리오 설정](../design/dispatch-scenarios.json)을 읽어 OSRM 도로 경로를 계산한다. dislab에서 기존 H28 Python 환경을 사용한다. `STREAM`은 `state-<Unix 시각>.json`과 그에 대응하는 `forecast-<Unix 시각>.npz`가 있는 비공개 폴더다.

```powershell
python tools/scenario_dispatch.py --stream STREAM --spec design/dispatch-scenarios.json --roads ROAD_CACHE --out OUTPUT
```

`plans.json`, 시나리오별 GeoJSON, `work-orders.csv`가 생성된다. GeoJSON에는 왕복 경로와 순서가 지정된 작업 위치가 들어 있다. HTML은 내려받아 브라우저에서 열고, 시나리오를 선택해 결과를 확인할 수 있다. 이 파일은 계산 결과를 조회하고 선택한 경로를 내보낸다. 새 계산은 위 프로그램에서 실행한다.

## 조건과 결과

기록 재생은 2026년 11월 10일의 19:50, 20:20, 20:50 관측을 사용했다. 수거와 배치에 한 곳 최소 3대, 정차 준비 60초, 상하차 20초/대를 적용했다. 대여소 작업은 예측 시각 30초 전까지 마치는 조건이다. 기본 복귀 마감은 출발 후 15분이다.

| 조건 | 수거·배치 순서 | 이동 | 왕복 | 작업시간 |
| --- | --- | ---: | ---: | ---: |
| 태평 19:50 | 버드내초등학교 → 유천동 278-30 | 6대 | 2.58km | 9.0분 |
| 태평 20:20 | 버드내초등학교 → 유천동 278-30 | 6대 | 2.58km | 9.0분 |
| 태평·문화 20:50 | 버드내초등학교 → 센트럴파크 | 6대 | 4.33km | 10.6분 |
| 둔산 20:50 | 탄방동 e편한세상 → 둔산동 샤크존 | 6대 | 2.46km | 10.1분 |
| 대전역 20:50 | 홍도아파트 버스정류장 → 대전역 동광장 | 4대 | 5.61km | 11.7분 |
| 태평 20:50, 복귀 8분 | 버드내초등학교 → 태평오거리 | 4대 | 1.83km | 7.4분 |
| 태평·문화 20:50, 빈자리 3대 가정 | 버드내초등학교 → 센트럴파크 | 3대 | 4.33km | 8.6분 |

20:50의 기본 세 권역은 차량 3대가 각 권역에서 독립적으로 출발한다는 가정이다. 작업하는 여섯 곳이 겹치지 않았고 합계 16대를 옮기는 계획을 계산했다. 세 권역의 이동 시간은 차량별 왕복 시간이다. 빈자리 3대 조건은 한 곳에 3대 배치를 선택했다. 모든 계산은 당시 예측에 기반한 기록 재생이다.

## 출발 전 검토

```powershell
python tools/review_dispatch_scenarios.py --plans OUTPUT/plans.json --prepare --out OUTPUT/review-request.json
python tools/run_dispatch_review_relay.py --request OUTPUT/review-request.json --relay-workspace RELAY --out OUTPUT/llm-relay.json
```

dislab에서 먼저 수량 보존, 적재량, 작업·복귀 시각과 작업 대상 중복을 검사한다. Antigravity에 넘기는 것은 검증한 요약과 선택 가능한 항목 ID다. `llm-relay.json`의 `candidate` 객체를 `candidate.json`으로 저장하고, 다음 명령으로 그 선택을 다시 검증한다. 선택이 유효하면 코드가 작성한 근거 문장을 원문 그대로 표시한다. 후보 파일을 생략하면 규칙에 따른 검토 순서를 만든다.

```powershell
python tools/review_dispatch_scenarios.py --plans OUTPUT/plans.json --candidate OUTPUT/candidate.json --out OUTPUT/review.json
```

실제 LLM 호출에서 첫 항목은 대전역의 배치 마감 여유 13초였다. 다음은 둔산의 배치 마감 여유 34초와 복귀 8분 조건의 복귀 여유 37초였다. 담당자는 마감 여유가 짧은 경로의 도로 지연과 현장 작업시간을 먼저 확인할 수 있다.
