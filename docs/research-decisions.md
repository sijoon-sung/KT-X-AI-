## 최신 자료 계약에 따른 판단

### 가설

후속 모델은 과거 기록으로 학습하고 API는 검증에만 사용한다.
GCN·포아송·Flow Matching의 역할은 과거 자료의 정답·구조와 문헌에서 다시 좁힌다.

### 실험

과거 대여이력 원본을 dislab에서 발견하고 ZIP 내부 20개 CSV의 해시·인코딩·열·날짜·월 일치 여부를 감사했다.
후속 H-0004에서 사전 규칙에 따른 거래 전처리·누락 마스크·학습 ID 고정과 두 평균 모형 학습을 수행했다.
API는 이번 과거 원본 감사에 사용하지 않았다.

### 결과

기존 H-0002는 API 학습 실험, H-0003은 API 자료 탐색이었다.
원래 판정과 수치는 보존하지만 새 모델의 학습·모형 선택 근거로 승계하지 않는다.
기존 API 기간은 이미 열람했으므로 미열람 독립 시험이 아니다.

H-0004는 대여소 1,192개·3월 1,037,040평가 칸에서 달력 평균의 deviance 개선율 11.35%를 보였다.
3일·7일 블록 구간은 10.11~12.91%·10.54~12.98%로 사전 1% 초과 가설을 지지했다.
이는 **보조 거래 건수 진단**이다. 2·3월 실측 재고 정답은 없으며 프로젝트의 재고 모형 채택·성능 판정으로 승계하지 않는다.

[H-0005 결과](H-0005-results.md)에서 고정한 과거 흐름·0반사 과정·현재 API 시작 상태를 연결해 **9월 API 공식 평가**를 완료했다.
계획·구현 모두 실행 전에 PR #10에 게시했다. 현재 양수 Brier 0.149934→0.119369,
감소 0.030565의 3일·7일 구간은 0.020927~0.036069·0.025101~0.035048로 사전 기준을 통과했다.
전체 수량 MAE는 0.579567→0.632669대로 악화했으므로 최종 운영 모델은 채택하지 않는다.

다음 행동은 [아이디어별 실험](architecture-ideas-to-experiments.md)에 따라 과거 학습 OD 관계·자기 대여소·치환 관계의 공간 비교를 새 가설로 구체화하는 것이다.
GCN·FM을 필수 조합으로 확정하지 않고, 시간 입력·출력·상태 모듈을 통제하며 하나의 축씩 비교한다.
과거 거래를 재고 실측값으로 바꾸지 않고, API를 학습·보정·구조 선택에 넣지 않는다. 최종 네트워크는 미정이다.

후속 [H-0006](H-0006-results.md)에서 **같은분포의 점출력·손실 불일치**를 진단했다.
평균→중앙값 MAE 감소0.056323대는 사전 기준을 통과했다. 현재유지대비 중앙값 개선0.003221대의
3일·7일 보조95%구간은 -0.003099~0.006731·-0.000073~0.004547로0을 포함했다.
중앙값의97.35%가 현재와 같았다. 평균RMSE1.149779는 현재유지1.202860보다 낮았다.
H5 수치를 수정하지 않고 그 평균MAE 악화를 분포 전체 실패로만 읽지 않는다는 해석을 추가했다.
재배치·계절 변화·독립 가정의 원인별 기여는 식별하지 못했으며 API로 보정하지 않았다.
[원인별 계획](failure-analysis-and-improvement-plan.md)에 따라 과거 공간 비교를 이어 가고 분포·결합 생성은 별도 질문으로 둔다.

[H-0007](H-0007-results.md)은 과거 전용 OD-GCN의 한조건을 실제 비교했다.
원본1,862,658개 비자기 학습OD로 관계를 만들고같은1762모수·각3seed를과거에서학습/선택했다.
9월에서 OD현재양수Brier0.120347은자기0.120283·치환0.120387과비슷하고고정달력0.119369보다높았다.
세대조군최소이득-0.000978의3일/7일구간은-0.001310~-0.000664·-0.001147~-0.000869로 사전0.002초과가설을지지하지않았다.
API에서승자를선택하지않고모형채택은보류했다. 정적프로필에는최근거래/도시충격정보가없다는입력제약을명시한다.
제안하는후속방향은과거순차시간이전·가용맥락검토와단순공동흐름대조군이며,모든GCN이나FM의결론으로확대하지않는다.

## 공모전 시제품 우선 진행: H-0008

사용자의 최신 요청에 따라 GCN의 추가 성능 우위와 별개로 **작동하는 예측시스템**을 우선한다.
[H-0008](H-0008-prediction-system.md)에서 기존 과거전용 GCN을 실제30분 예측 API·CLI·화면에 연결했다.
9월기록 재생·수동현재상태·현재스냅샷JSON을 지원하며 대표대수·0대확률·범위·달력참고출력을 보여 준다.
미래정답조회는예측입력과별도다. dislab에서64개고정예측을재현하고기능검사를통과했다.
시제품연결을채택하며H7의부정결과/성능미채택은보존한다. 새학습·API튜닝·보정은없다.
실시간연동과현장운영검증은별도후속작업이다. 당장의진행순서는입출력·시연완성도,그다음새가설별성능개선이다.

## 규모 확대·따릉이·CFM 실제 학습: H-0009

사용자 요청에 따라 작은/큰 GCN, 서울 과거 패턴 특성, GCN조건부 Flow Matching을 실제 학습했다.
[H-0009 결과](H-0009-scaled-seoul-flow.md): 공식9월 최소 대조군 상대 CRPS 감소 -0.371%, 판정 `not_supported`.
시드당 큰 GCN75,394개+CFM50,818개를 사용하며 각2시드다. 서울은2017~18년 UCI도시 대여 패턴 네 특성이다.
과거30분 실제 거래로 학습·2월에서 가중치를 선택하고, 생성 표본까지 동결한 뒤9월API로만 재고를 평가했다.
공모전 요청에 따른 새 연구 후보를 시제품에 연결하며, API 점수로 우승 모델·구조·보정값을 선택하지 않는다.
2·3월 건수 진단과9월 재고 평가를 구분하고 모든 실패·불확실성 및 기존H7 결과를 보존한다.

## 관리자 재배치 지원 방향

### 가설

사용자의 운영자 관점을 우선해 [관리자 재배치 시스템 기획](operator-rebalancing-plan.md)을 다음 제품 방향으로 삼는다.
목표는 부족 위험·공급 후보·작업 제약의 연결이며 새 예측 모델의 성능 우위를 전제하지 않는다.

### 실험

공식 정책·이용 안내·뉴스·차량 보험 공고 재게시본으로 운영 근거를 확인하고 모델의 역할과 자료 공백을 정리했다.
H9은 대여소별 대여/반납 두 건수의 생성이며 도시 전체 공동 시나리오나 차량 경로 모형이 아니다.

### 결과

관리자 현황판 → 수량 비교 → 차량 경로 순서를 채택한다. 이번 변경은 문서 기획이며 후속 구현·운영 실험은 미실행이다.
보험 대상 14대·2024년 정비센터 4곳을 현재 실가동 차량·출발 거점으로 대입하지 않는다.
차량별 적재량·가동 여부·근무시간·정상 자전거·허용 주차 구역은 추가 운영 입력으로 남긴다.
9월 API의 모델/임계값 선택·보정 금지는 유지하고, 재배치의 실제 개선은 별도 운영 로그와 검증 설계가 있어야 판정한다.

## 예측 모델 개선을 우선한 H-0010

### 가설

사용자 최신 요청에 따라 다음 개발의 우선순위는 예측 성능 개선이다.
[H-0010](H-0010-seasonal-history.md)에서 넓은 이력의 대여소별 계절 패턴과 작은 GCN 잔차를 비교했다.

### 실험

2024-08~2026-01의 과거 기록·첫 기록 이전 노출 마스크·월별 계층 평활을 사용했다.
2월 거래로 alpha/checkpoint를 선택하고 가중치·출력·수치 근사를 고정한 뒤 9월 재고를 평가했다.
같은 넓은 이력의 비계절 달력·계절 평활·자기 대여소/OD-GCN과 기존 H9를 구분했다.

### 결과

판정 `not_supported`, 두 주대조군 최소 CRPS 상대 감소 0.243%. 연구 모델을 보존하며 API로 배포 승자를 고르지 않는다.
2월에서 선택한 GCN의 3월 건수 오차는 계절 평활보다 높았다. 원인을 확정하지 않고 과거 여러 계절의 시간 분할과 긴 예측 공백 대응을 다음 연구 질문으로 둔다.
관리자 기능 계획은 유지하며 후속 모델 실험을 우선한다. 모든 후속 비교는 새 가설에서 동결하고 API 검증 전용 계약을 유지한다.


## H-0013 · 최근 API 입력으로 다음10분을 예측하기

### 가설

[H-0013](H-0013-rolling-api-flow.md)은 서울 미래 거래 예측 encoder·타슈 GCN·조건부 Flow Matching으로 최근 관측을 받아10분 재고를 예측한다.
현재유지와 동일GCN Poisson 모두 대비 fairCRPS1% 초과 감소를 사전에 정했다. H12의 거래 건수 성능과 이번 재고 성능을 구분한다.

### 실험

24시간/10분 과거 완료 거래만 학습·2월 선택, 전체weights·생성·평가계획을 잠근 뒤9월 API를 시간순 재생했다.
직전/현재 API는 추론 입력, 미래 API는 별도 정답이다. API 차이는 운영 이동을 포함한 대리값이며 재배치 행동 정답이 아니다.
GCN no_recent/recent각2시드와CFM2시드,128IID 입자·Heun16·동일 재고투영·3/7일 도시동기화calendar-day구간이다.
로컬 학습 위치 위반을 보존하고 부분 로컬 평가는 중단했다. 전체9월 평가·실제 새추론·채점은 dislab에서 완료했다.

### 결과

9월1,298ID/2,458,501쌍, CFM fairCRPS 현재유지 대비15.215% 감소·같은GCN Poisson 대비0.327% 악화, 주가설 `not_supported`.
대수 MAE는0.211982대로 현재유지0.212015대와 거의 같았다. 15.215%를 대수 정확도 개선으로 읽지 않는다.
실제21:20·21:30 API→21:40 관측1,296쌍을 발행 후 채점했다. 이 회차는 기능·추가 관측이며 공식9월을 대체하지 않는다.
같은 고정모델의 예측·위험 참고목록을 보존하고, 다음 연구는 과거 내부 검증의 CFM 분포 손실/선택 기준과 실제 기상 수신이다.
API로 승자·구조·보정을 다시 고르지 않는다. 차량·적재·거점·action/cost/outcome이 없어 RL 정책과 재배치 효용은 별도 단계다.
실시간 경로는 독립CLI이며 기존8768화면은H9다. 고정 계획·실패·환경 차이·시계 차이·검사는 연결한 보고서에 남긴다.


## H-0016 · 실제 결과와 재배치 작업표를 이어 보기

### 가설

실제 발행·다음 관측·채점과 가정에 따른 수량/동선을 한 화면에서 구분해 따라갈 수 있게 한다.

### 실험

기존 H13 기록·H14/H15 결과의 해시를 고정하고 PR23에 계획을 게시한 뒤 dislab CPU에서 묶음을 생성했다.
미래 관측을 열기 전에 후보와 계획을 봉인했다. 과거 모델의 새 학습·승자 선택·새 타슈 API 수집은 하지 않았다.
실제 좌표의 OSRM 추정과 가상 자원 입력을 연결하고 로컬 화면은 완성된 결과를 표시한다.

### 결과

1,296개 대응과 원래 모든 점수 재현, 원격 기능 검사13개 실패0, 브라우저 정상 상호작용 검사10개 통과다.
실제 대여소 기반 그림자계획은4대 이동·6.093분 복귀이며 운영 자원·거점·작업·주차 가정을 명시했다.
실제 재배치 효과·새 예측 우월성은 미검증이다. 추가 오류 주입 브라우저 시험은 자동 승인 거부로 미실행이며 통과 목록에 넣지 않았다.
[화면과 재현 안내](H-0016-results-walkthrough.md), [PR23](https://github.com/sijoon-sung/KT-X-AI-/pull/23)에서 이어 간다.
다음은30/60분 도착시점 예측·확인된 자원/도로/행동 로그를 별도 가설로 갖추는 것이다.


## H-0017 · 운영 지도와 동적 거리·수량·순서 계산

### 가설
