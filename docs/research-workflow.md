# 타슈 연구·개발 진행 체계

연구 가설마다 Draft PR을 먼저 만들고, 그 PR에서 문헌·계획·실험·판단을 이어 간다.
가설을 만들기 전에는 [연구 프로그램](research-program.md)에서 문제·자료·가정과 후보 모형군을 먼저 좁힌다.
특정 아키텍처를 완성본으로 가정하지 않고 [결정 기록](research-decisions.md)에 선택 근거를 남긴다.
기존 `main`, `성시준`, `contest/*` 브랜치는 참고 기록이다. 새 연구의 기준선과 성능은 별도로 재현한다.

## 1. 질문과 문헌

무엇을 설명하거나 예측할지 한 문장으로 쓴다. 관련 연구의 정답, 입력, 가정, 평가를 비교한다.
이미 제안된 방법과 추가로 검증할 부분을 구분하고 공식 원문 링크와 확인 범위를 기록한다.
현재 자료에서 직접 관측할 수 없는 대상을 정답으로 취급하지 않는다.

## 2. 가설과 Draft PR

ID 중복 여부는 원격 PR과 `research/hypotheses/`에서 확인한다.
하나의 가설은 하나의 결과 비교 질문을 다룬다. 여러 모델은 같은 가설 안의 비교군이 될 수 있다.

```bash
git switch main
git pull --ff-only
git switch -c hypothesis/H-0001-observation-resolution
python tools/research.py new H-0001 --title "관측 간격이 품절 평가에 주는 영향"
```

생성된 JSON의 계획을 작성하고 커밋·push한 다음 Draft PR을 연다.
GitHub 연결 도구로 같은 작업을 수행해도 된다. CLI 예시는 다음과 같다.

```bash
gh pr create --draft --base main --title "[H-0001] 관측 간격이 품절 평가에 주는 영향" --body-file path/to/pr-body.md
```

연구 질문만 구상한 `planned` 단계는 TODO를 허용한다. 검사를 통과했다는 이유로 실험을 시작하지 않는다.
이슈는 자료 접근·데이터 이상·선행연구 확인을 추적하는 보조 수단이다.

## 3. 실험 전에 계획 동결

다음 항목을 먼저 확정한다.

- 반증 가능한 가설과 관련 선행연구
- 자료 식별자, 관측 정답, 직접 관측하지 못하는 대상
- 학습·검증·시험 또는 짝지은 관측 비교 설계
- 비교 기준, 주 지표와 방향, 성공·실패 판단 규칙
- 누락·중복·이상치 제외 규칙, 불확실성 평가와 시드 계획

```bash
python tools/research.py freeze H-0001
python tools/research.py check
```

계획은 정규화한 JSON의 SHA-256으로 고정한다. 이 커밋을 PR에 push한 뒤 실험한다.
해시는 사후 변경을 발견하는 보조 장치다. PR의 계획 커밋 시각과 실행 기록도 함께 검토해야 한다.
한번 동결한 ID의 계획은 바꾸지 않는다. 변경 실험은 새 ID와 새 PR을 만든다.

## 4. 실행과 결과

가설 상태는 `planned → preregistered → running → completed`로 진행한다.
철회는 `withdrawn`과 이유를 남긴다. 완료 시 결론은 `supported`, `not_supported`, `inconclusive` 중 하나다.
결론은 사전 정의한 조건과 증거를 근거로 사람이 검토한다. 형식 검사가 통계 판단을 대신하지 않는다.

실행마다 `research/templates/run-manifest.json`을 복사해
`research/runs/<run-id>/manifest.json`을 만든다. 원본 자료와 큰 출력은 저장소 밖에 보관한다.
실행 manifest에는 가설·계획 해시·코드 커밋·입력 해시·환경·명령·시드·기간·실측 지표를 적는다.
가설 JSON의 `result.run_manifests`에서 해당 파일을 연결한다.
같은 데이터에서 반복 선택했다면 최종 보고서에 선택 절차와 시험 자료 재사용을 명시한다.

## 5. 검토와 병합

PR에는 변경 이유, 계획, 결과, 재현 명령, 결론과 한계를 남긴다.
효과가 없었던 실험도 연구 기록으로 병합할 수 있으며, 그 구현을 기본 실행 경로에 채택하는 것은 별도 판단이다.
코드 채택 여부는 `result.adopt_code`에 기록한다. `false`여도 결과 기록은 보존한다.
사용자가 병합을 지시하기 전까지는 PR로 남긴다. 원격 검사 완료를 확인하지 않았으면 그렇게 보고한다.

## 자동 검사

`Research protocol` 작업은 계획 형식, 동결 뒤 변경, 완료 결과의 실행 근거와 PR별 가설 ID를 검사한다.
`[H-0001]` PR은 해당 가설 파일을 반드시 포함하고 다른 가설 파일을 함께 바꾸지 않는다.
`[workflow]`는 운영 문서·템플릿·검사 도구만, `[maintenance]`는 비실험 변경만 허용한다.
학습·예측·전처리 구현을 바꾸는 작업은 가설 PR로 기록한다.
Draft PR이 완료·철회 기록까지 갖추면 일반 PR로 전환한다.

검사를 병합 필수 조건으로 강제하려면 GitHub에서 `main` 규칙에 `research-protocol`을
필수 상태 검사로 지정해야 한다. 이 설정은 아직 이 파일만으로 적용되지 않는다.

## 자료 공개 범위

API의 `.env`, 토큰, 원본 백업 ZIP, 개인 경로·인증정보를 PR에 포함하지 않는다.
공개 데이터셋은 사용 조건을 확인한 후 링크한다. 비공개 원본은 식별자·기간·스키마·SHA-256만 기록한다.
재고 자료만 있는 경우 거래량·잠재 수요·고장 정답·개입 효과가 관측된 것으로 설명하지 않는다.

후속 연산은 dislab에서 수행하고, 새 비교·기간·학습 예산은 새 가설로 동결한다.
