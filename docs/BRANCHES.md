# 브랜치 운영

| 브랜치 | 역할 | 처리 |
|---|---|---|
| main | 기존 공개 기록과 통합 기준 | 검토 전 덮어쓰기/강제 push 없음 |
| contest/rebuild-pipeline | 새 공모전용 구현 | 코드·테스트·문서를 모으는 브랜치 |
| 성시준 | 기존 개인 작업/시각화 | 보존. 미검증 수치·표현 자동 병합 없음 |

기반은 ecb4a43입니다. 기존 tashu/를 삭제·이동하지 않고 공식 실행 코드를
src/tashu_contest로 분리했습니다. 모델/결과 기록과 개인 작업을 보존합니다.

1. 이 브랜치를 검토한 뒤 main으로 일반 PR 병합합니다.
2. 이후 입력 어댑터·모델 개선·발표 화면은 목적별 짧은 브랜치로 작업합니다.
   예: contest/data-adapter, contest/stock-calibration, contest/presentation.
   이는 향후 이름 예시이며 빈 브랜치를 미리 만들지 않습니다.
3. 원본/가중치/실행 결과는 커밋하지 않고 runs/에서 실행별로 보관합니다.
4. 최종 평가로 튜닝한 뒤 같은 결과를 독립 시험 결과로 부르지 않습니다.
5. 개인 브랜치의 시각화를 옮기면 새 recommendation.json에 연결합니다.
   과거 하드코딩 수치·물리 법칙·정책 효과 주장을 함께 가져오지 않습니다.

브랜치 삭제·force push·공유 히스토리 재작성은 이번 작업에 포함하지 않습니다.
