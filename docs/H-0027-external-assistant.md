# H-0027: 외부 LLM과 2분 시연

## 가설

외부 LLM이 알려진 운영 질문 10개 중 9개 이상에 실제 모델 답변을 제공하고, 필수 기능 검사 6개를 통과하며 CLI·HTTP·화면으로 연결되는지 확인한다. 예측 정확도를 높이는 실험은 아니다. [PR39](https://github.com/sijoon-sung/KT-X-AI-/pull/39)에 계획을 먼저 동결했다.

## 실험

`gemini-3.8-flash-low`와 정상 로그인한 공식 Antigravity CLI 1.4.10을 사용했다. dislab이 질문에 필요한 사실과 출력 형식을 준비하고, 이 컴퓨터의 CLI는 외부 모델 요청을 중계했다. 수량·방문지·순서·근거 ID·자료 버전 검사는 dislab에서 수행했다. 로컬 GPU나 Qwen으로 조용히 대체하지 않았다.

개발 확인 3회 뒤 정상 질문 10개, 필수 6검사, 기존 H21의 긴 6방문 계획을 한 번 시험했다. 이미 알려진 합성 예시와 기록 계획을 이용한 기능 시험이다. 새 모델의 일반 언어능력이나 비전공자 이해도를 측정한 시험은 아니다. 초기 한글 전송 실패, 긴 요청의 전송 실패와 후속 수정도 보존했다.

실제 화면 연결에는 2026년 11월 10일의 새 API 관측 기록을 사용했다. 기존 H18 고정 예측 경로를 최대 7관측·70분으로 실행해 7회 수신·6회 발행 후 다음 관측 연결을 마쳤다. 마지막 관측은 20:50, 지원 대여소는 1,294곳이다. 수집은 예산을 마쳐 중지됐다. 가중치·분포·임계값은 바꾸지 않았다. 9월 공식 평가를 다시 열거나 대체하지 않았다.

## 결과

**기능 연결 가설은 지지됐다.** 정상 질문 10개 모두 실제 외부 답변으로 통과했고 필수 검사 6개도 통과했다. 긴 6방문 계획은 방문지와 순서를 빠뜨리지 않았다. HTTP에서 실제 외부 답변과 `engine: external`을 확인했고, 화면에서도 질문·답변·지도 연결을 확인했다.

| 확인 항목 | 결과 |
|---|---:|
| 알려진 정상 질문 / 실제 외부 답변 | 10/10 |
| 필수 기능 검사 | 6/6 |
| HTTP·정적 파일·잘못된 입력 처리 | 10/10 |
| 기록·회차 일치·중지 스트림 처리 | 6/6 |
| 기존 수량·순서·0대 답변 오류의 회귀 검사 | 5/5 |

H26의 첫 실제 Qwen 답변 7/10 결과는 그대로 남긴다. 이번에는 모델뿐 아니라 프롬프트·자료 선별·전송·검사도 달라졌다. 두 점수 차이를 모델 크기만의 효과로 해석하지 않는다. 숫자와 이름 검사를 통과했다고 모든 한국어 문장의 의미가 보장되는 것도 아니다.

### 같은 기록으로 계산한 이동 계획

20:50 관측, 21:00 예측을 재생하고 관측 후 15초에 출발하는 조건으로 H21 계획을 계산했다. 도로 거리와 상하차 시간을 포함했다. 차량 조건은 가정이다.

| 적재량 가정 | 총 이동 | 방문 | 도로 거리 | 예상 시간 |
|---|---:|---:|---:|---:|
| 20대 | 5대 | 8곳 | 5.2641km | 9.1367분 |
| 1대 | 3대 | 6곳 | 약 6.51km | 약 9.2분 |

20대 조건의 보존·중간 적재·공급지 보호·예측 시간 내 복귀 검사에서 위반은 0건이었다. 지원 1,294곳에서 25곳을 후보로 좁힌 제한된 탐색이며 도시 전체 최적해나 실제 운행 절감 결과가 아니다. 0대 관측 593곳 중 이번 계획의 공급 대상은 4곳이다. 한 차량으로 모든 부족을 해결했다고 해석하지 않는다.

지도에서 조건을 바꾸면 dislab에서 다시 계산하고, LLM은 가장 최근 계획을 읽는다. 서로 다른 관측 회차를 합치거나 답변 생성 중 바뀐 계획의 오래된 답변을 발행하지 않는다. 지난 자료에는 ‘기록 재생’을 표시한다. 중지·만료된 스트림으로 실시간 계획을 요청하면 거절한다.

### 제공한 결과물

- [2분 시연 영상](../assets/demo/tashu-demo-2min.mp4): 1920×1080, 한국어 음성·자막. 실제 브라우저 화면을 캡처해 편집했고 응답 대기는 줄였다. 전체 디코딩과 7지점 화면 검수를 마쳤다.
- [실행·시작·중지 안내](quickstart-external-llm.md): 현재 Antigravity 연결과 일반 외부 HTTP API 설정을 구분한다. OpenAI 키가 없는 상태를 연결 완료라고 보고하지 않는다.
- [서비스 구성도](service-composition.md): 워크시트 8번 슬라이드는 도형·문자·연결선을 수정할 수 있다. ‘10분 뒤 자전거가 부족할 대여소’로 표현을 바꿨다.
- [실행 기록](../research/runs/H-0027-20261110-external-assistant/): 개발 실패 3회, 첫 고정 답변, 서비스 답변, 영상 검수와 해시를 보존했다.

이 컴퓨터의 로그인 작업으로 내부 화면을 실행했다. 공개 인터넷 배포·실제 배차·PR 병합은 하지 않았다. 다음 현장 단계는 운영 조건을 확인하고 담당자가 계획을 검토하는 시범 운영이다.

### 후속 화면 보완

세 질문은 ‘전체 재배치 계획 알려줘’ 하나로 합쳤다. 총대수·거리·예상 시간과 모든 방문지의 수거·배치 대수를 함께 제공한다. 추가 실제 화면 확인에서도 8곳의 순서와 수량을 확인했다. 기존 5개 오류 검사에 통합 질문·방문지별 수량 검사 2개를 더해 7개를 통과했다. 첫 고정 10질문 결과를 다시 측정하거나 바꾸지 않았다.

프로젝트 설명은 관측·이용 흐름 예측·부족 위험·재배치 수량과 동선·운영자 설명을 연결하는 운영 도우미로 정리했다. 10분은 현재 검증한 재고 예측 구간이다. 지도 도로 표시도 확인하고 통합 질문을 2분 영상에 반영했다.

8곳을 방문해 5대를 옮기는 예시는 기능 연결 확인용이다. 1대씩 분산 배치하는 계획의 현장 효율을 입증하지 않는다. 기존 계산은 자전거 1대당 상하차 시간만 반영하므로 정차·작업 준비 비용과 묶음 작업을 별도 계획 연구에서 확인해야 한다.
