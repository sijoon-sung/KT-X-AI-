# 타슈 예측 연구: 문제의식과 해결 계획

작성일: 2026-10-31. 상태: 연구 기획과 1차 검증 기록. 운영 개선을 입증한 문서가 아니다.
공식 재고·품절 평가는 [2026년 9월 API 수집본](september-evaluation-contract.md)에 고정한다.
2·3월 다운로드 이력에는 거래 건수만 있고 실측 재고·품절 정답은 없다. 건수 비교는 보조 진단이다.
최신 자료 사용은 [과거 이력 학습·API 검증 전용 계약](training-validation-contract.md)이 우선한다.
학습·모형 선택은 과거 기록에서 수행하고 API는 외부 검증에만 사용한다.
아래 API 기반 H-0001~H-0003과 그 설계 해석은 계약 변경 전의 기록이며 후속 모델의 선택 근거로 승계하지 않는다.
현재의 상위 설계는 [연구 프로그램](research-program.md)과 [결정 기록](research-decisions.md)에서 이어 간다.
진행 규칙은 [연구 체계](research-workflow.md), 첫 검증 계획은 [H-0001](H-0001-observation-resolution.md)을 따른다.

## 1. 이 프로젝트를 왜 다시 시작하는가

이 대화에서 확인한 출발점은 기존 결과의 신뢰성을 다시 점검하고 싶다는 요구다.
기존 GitHub·Drive 작업에서는 아이디어를 가져오되, API 관측을 근거로 정답을 정의하고,
문헌 조사와 검증 기록을 쌓아 새 연구를 진행하기로 했다. 기존 점수를 새 실험 결과로 승계하지 않는다.
사용자가 특정 대여소에서 겪은 경험이나 현장 인터뷰를 했다고 가정하지 않는다.

우리가 풀고자 하는 서비스 문제는 다음과 같이 제안한다.

> 타슈 이용자와 운영자가 현재 재고를 확인하는 데서 더 나아가,
> 필요한 미래 시점의 대여소 상태를 어느 정도 믿고 판단할 수 있게 한다.

예를 들어 이용자는 대여소로 이동한 뒤의 상태가 궁금할 수 있고,
운영자는 자전거를 옮기는 데 걸리는 시간 이후의 상태가 필요할 수 있다.
이는 조사할 사용 상황이며, 수요가 검증된 제품 요구사항은 아니다.
이용자의 이동 시간과 운영자의 출동 시간도 아직 측정하지 않았다.

1차 연구 대상은 **대여소별 API 표시 재고의 미래 상태와 그 예측의 신뢰성**이다.
최초 산출물은 관측 품질 보고서와 재현 가능한 예측 평가다.
그 다음 이용자용 정보 화면을 검토하고, 운영 기록을 확보한 뒤 재배치 판단 지원으로 확장한다.

## 2. 공식 자료와 선행연구가 알려주는 것

조사 기준일은 2026-10-31이다. 아래는 이번 기획에 직접 연결되는 근거다.
인용한 사례의 성능을 타슈의 현재 자료에 그대로 적용하지 않는다.

| 확인한 근거 | 확인 범위 | 기획에 반영할 판단 |
|---|---|---|
| [타슈 공식 안내·Open API](https://www.tashu.or.kr/main.do) | 이용 안내, API 제공 항목·응답 예시. `parking_count`의 공식 의미는 대여가능 자전거 수량 | 대여소 ID·위치·재고 응답을 기본 관측으로 삼는다. 이 응답만으로 현장 고장 여부까지 검증하지는 못한다 |
| [행정안전부, 2017-10-16](https://www.mois.go.kr/frt/bbs/type010/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000008&nttId=59951) | 타슈 대여·반납, 대중교통·주변 환경을 결합한 분석과 기계학습 기반 신규 대여소 후보 선정에 관한 공식 보도자료 | 타슈의 데이터 분석·주변 환경 결합 자체를 새 아이디어라고 주장할 수 없다. 당시 자료·운영 체계와 현재 자료는 다르다 |
| [Feng 외, 2017](https://www.pure.ed.ac.uk/ws/portalfiles/portal/44197453/peva_bike.pdf) | 저자 공개 원고의 초록·방법 개요. 현재 상태와 역사적 이용 정보를 통한 미래 재고 분포 예측 | 미래 재고의 확률 예측은 기존 연구 영역이다. 거래 정보가 필요한 방법은 재고 관측만으로 완전히 재현할 수 없다 |
| [Zhao 외, 2021](https://www.sciencedirect.com/science/article/pii/S1361920921002121) | 출판사 검색에 노출된 자료·샘플링·결론 절. 전체 PDF 검토·재현은 미완료 | 관측 간격과 처리 방식이 결과에 주는 영향도 선행연구가 있다. 차량별 위치에서 이동을 복원하는 연구와 대여소 집계 재고를 구분한다 |
| [Gammelli 외, 2020](https://arxiv.org/abs/2001.07402) | 저자 원문의 절단 수요 모형과 자전거 실험 | 공급에 의해 드러나지 않은 수요는 별도 추정 문제다. 재고 감소량을 수요 정답으로 바꾸지 않는다 |
| [Gammelli 외, 2022](https://ris.utwente.nl/ws/portalfiles/portal/277299225/10.1016_j.trc.2022.103571.pdf) | 공개 출판 원문의 예측·재고 의사결정 비교 | 예측 오차 개선과 재배치 효과는 별도로 검증한다 |
| [Nejadshamsi 외, 2026](https://www.sciencedirect.com/science/article/pii/S0950705125020246) | 출판사 검색에 노출된 초록·방법·정답 정의. 전체 구현 재현은 미완료 | 동적 그래프·시간 패턴·날씨를 이용한 대여·반납 공동 예측은 이미 존재한다. 그래프를 붙이는 것만으로 기여가 성립하지 않는다 |
| [Byrd 외, 2026](https://pubsonline.informs.org/doi/10.1287/msom.2025.0391) | 출판사 초록의 거의 분 단위 Capital Bikeshare 상태 자료 설명 | 더 촘촘한 외부 자료는 관측 한계의 비교 후보다. 파일 접근·사용 조건·품질은 아직 확인하지 않았다 |

현재 조사로 확정할 수 있는 것은 연구 주제가 이미 풍부하다는 점이다.
전체 문헌을 빠짐없이 검토한 것은 아니므로, 아직 논문 신규성을 주장하지 않는다.
추가 검색은 availability/status forecasting, temporal sampling, stockout/recovery,
censored demand, forecast-to-decision evaluation의 인용·피인용 문헌으로 확장한다.
논문별 입력·정답·시간 간격·시간 분할·비교군·코드/자료 접근성을 같은 표로 비교한 뒤 기여를 좁힌다.

## 3. 우리가 가진 자료와 정답의 경계

Drive 백업의 타슈 주 수집 자료에 대한 기존 전처리 중간 점검은 다음과 같다.
아래 숫자는 **재감사 전의 예비 집계**이며, 연구 결과나 서비스 수준의 확정 통계가 아니다.

| 항목 | 예비 확인 내용 | 해석상 주의 |
|---|---|---|
| 기간 | 2026-09-17 14:14:16 ~ 2026-10-30 16:40:01, 44개 일자 파일 | 시작·종료일은 부분 일자. 수집기 시간대를 한국 시간으로 해석한 상태이며 운영체제 시간대 증거가 없다 |
| 원본 행 | 8,529,628행 | 같은 시각의 여러 대여소와 반복 관측을 포함한다. 독립적인 시간 표본 853만 개가 아니다 |
| 대여소 | 고유 ID 1,383개 | 현재 운영 중인 공식 대여소 수와 같다고 단정하지 않는다 |
| 관측 간격 | 전처리에서 10분 격자, 격자 이후 120초 이내 요청 시각을 허용 | 서버 갱신 주기나 응답 지연 상한을 확인한 것이 아니다. 원래 요청 시각도 보존한다 |
| 누락 | 전체 관측이 없는 격자 24개, 전체 직사각형 패널의 미관측 칸 73,898개 | 미설치·운영 변경·통신 누락을 모두 같은 원인으로 취급하지 않는다. 0으로 대체하지 않는다 |
| 0대 응답 | 유지된 관측 칸의 약 46.91% | 실제 시간의 품절률, 고객 실패율, 미충족 수요 비율을 뜻하지 않는다 |

공개 저장소에는 원본·인증키·개인 경로를 올리지 않는다.
가설 동결 전에는 공개 가능한 입력 목록과 해시, 집계 근거, 전처리 규칙을 별도로 확정한다.

정답으로 쓸 수 있는 것은 수집 요청에 대한 API의 `parking_count` 응답이다.
서버 내부 재고 갱신 시각이나 현장의 실제 이용 가능 상태와 일치하는지는 별도 점검 대상이다.

| 대상 | 현재 자료로 가능한 해석 |
|---|---|
| 지정된 미래 관측에서 0대인지 | 해당 관측이 유효할 때 직접 평가 가능 |
| 현재 0대인 곳이 미래 관측에서 양수인지 | 관측 상태의 회복으로 평가 가능. 이용자 반납과 운영자 재배치의 원인은 구분 불가 |
| 여러 관측 중 0대가 나타났는지 | 관측된 사건으로 평가 가능. 관측 사이의 사건은 미확인 |
| 정확히 언제 처음 0대가 되었는지 | 10분 관측만으로 연속 시간의 최초 사건 시각을 확정 불가 |
| 개별 대여·반납, 이용하려다 실패한 사람 수 | 직접 관측하지 못함 |
| 다른 재배치 정책을 썼다면 생겼을 결과 | 직접 관측하지 못함 |

재고 변화에는 대여·반납 외에도 재배치와 상태 보정 등이 섞일 수 있다.
예를 들어 재고가 그대로여도 그 사이 대여와 반납이 모두 발생했을 수 있다.
따라서 재고 차이를 거래량으로 이름만 바꿔 학습하지 않는다.

## 4. 문제를 풀어 가는 순서

각 단계는 산출물과 다음 단계로 넘어갈 조건을 갖는다. 기간은 확정 일정 대신 작업 순서로 제안한다.

| 단계 | 구체적인 작업 | 산출물·진행 조건 |
|---|---|---|
| ① 사용 상황과 기존 해법 조사 | 이용자의 이동 시간·정보 사용 방식, 운영자의 출동 시간·차량 제약·현재 판단 방식 조사. 기존 타슈 사업과 논문의 자료·목표 비교 | 확인된 요구와 미확인 가정을 구분한 요구사항표. 인터뷰는 아직 미실시 |
| ② 관측 신뢰성 확립 | 원본 목록·해시 재점검, 시간대·요청 시각·누락·ID 변경·이상 재고 점검. H-0001에서 관측 간격에 따른 요약 민감도 평가 | 데이터 설명서, 제외 내역, 관측 범위에 맞는 정답 정의. 문제가 크면 수집·정의부터 보완 |
| ③ 단순 기준선 평가 | 현재 재고 유지, 과거 시간대 통계, 현재 재고·자기 이력을 이용한 간단한 모형 비교 | H-0002에서 30분 뒤 관측 0대 확률을 비교했다. 다른 시간 범위는 미검증 |
| ④ 필요한 정보만 추가 | 주변 대여소 정보를 같은 기준선에 추가한 비교. 날씨·대중교통 정보는 추가 가치와 수집 비용을 별도 질문으로 검토 | 개선 크기·불확실성·추론 시간·자료 비용을 함께 기록. 효과가 없으면 단순 모형 유지 |
| ⑤ 예측 화면 검증 | 현재 상태·관측 시각·미래 시점의 0대 확률·불확실성·자료 누락 안내를 시제품에서 검토 | 이용자가 정보를 이해하고 판단에 사용하는지 확인. API 평가와 실제 대여 성공을 구분 |
| ⑥ 운영 판단 검증 | 재배치 시각·수량·차량·이동 시간·가능하면 이용 실패 기록 확보. 비교 가능한 운영 시험 설계 | 현장 운영 개선 근거. 확보 전에는 위험 요약·검토 후보까지 제공하고 최적 정책 효과를 주장하지 않음 |

①의 요구 조사는 ②의 데이터 설명 작업과 함께 진행할 수 있다.
운영자 접촉이나 외부 메시지 발송은 아직 수행하지 않았다.
②의 입력 감사·계획 동결 뒤 H-0001과 H-0002를 실행했다.
H-0002에서 단순 직접 예측을 기준으로 삼을 근거를 얻었으며, 생성형 모형의 추가 가치는 지지하지 않았다.
실사용 모형 채택과 새 기간 검증은 아직 남아 있다.

## 5. 이후 예측 실험에서 지킬 평가 원칙

30분·60분 뒤 예측은 현재 자료 간격과 맞는 후보일 뿐이다.
실제 필요한 시간 범위는 사용 상황 조사 후, 각 가설을 동결할 때 정한다.
시간 격자를 쓸 경우 허용 시차와 실제 경과 시간의 분포도 명시한다.

- 과거 학습 → 이후 검증 → 가장 나중 시험의 시간 순서를 지킨다. 같은 날짜의 대여소 행을 무작위로 나누지 않는다.
- 입력 이력·정답 구간이 경계를 넘는 표본을 제거하고 최대 예측 구간만큼 경계를 비운다. 정확한 기간은 후속 가설에서 동결한다.
- 검증 자료로 모형·확률 보정·경보 기준을 정한 뒤 시험한다. 이미 탐색에 쓴 기간은 그 사실을 남기고, 필요하면 새 수집 기간으로 전향 평가한다.
- 현재 0대인 곳의 미래 상태와 현재 양수인 곳의 미래 0대 위험을 나눠 보고한다. 계속 0대라고 말하는 예측의 성능이 전환 예측의 성능처럼 보이지 않게 한다.
- 재고 예측에는 MAE, 0대 확률에는 Brier score·확률 보정 상태를 우선 검토한다. 평균 정확도 하나로 판단하지 않고 날짜별·대여소별·상태별 성능을 함께 본다.
- 불확실성은 날짜·공통 도시 상황의 의존성을 고려한다. 모든 행이 독립이라는 전제로 좁은 오차 범위를 만들지 않는다.
- 입력은 예측 요청 시점에 이미 알 수 있던 정보만 쓴다. 날씨를 추가할 때도 나중의 실측 날씨를 당시 예보처럼 쓰지 않는다.
- 누락은 누락으로 남기고 평가 가능한 표본 수와 제외 사유를 보고한다. 누락 때 억지로 확신하는 예측을 내지 않는 기준도 검토한다.

44일의 한 계절 자료만으로 연중·다른 도시·새 운영 정책에 대한 일반화를 입증할 수 없다.
현재 운영 아래에서 맞춘 예측이 재배치를 바꾼 뒤에도 같은 성능을 유지한다고 가정하지 않는다.

## 6. 무엇이 이 프로젝트의 성과인가

첫 성과는 자료와 정답 정의를 다른 사람이 추적할 수 있는 상태다.
그 다음은 단순 기준선에 비해 미래 관측 예측이 얼마나 개선되었는지, 어느 조건에서 실패하는지 보여주는 것이다.
그 뒤에야 정보 화면의 유용성과 운영 효과를 평가한다.

자료 처리의 영향을 이미 다룬 연구를 타슈에서 다시 확인하는 것은 재현·적용 검증으로 가치가 있다.
그 자체를 방법론적 신규성으로 설명하지 않는다.
후속 기여는 관측 제약·상태별 신뢰성·추가 정보의 가치 가운데 실제로 남아 있는 질문을 문헌과 실험으로 좁힌다.

효과가 없는 결과도 다음 투자를 결정하는 근거다.
특정 복잡한 모형을 채택하거나 좋은 점수를 얻는 것을 연구의 필수 결론으로 두지 않는다.

## 7. 지금 실행할 첫 번째 일

첫 가설 [H-0001](../research/hypotheses/H-0001.json)은
**10분 자료를 30분 간격으로 보았을 때 대여소별 관측 0대 비율이 실질적으로 달라지는지**다.
모델 학습에 앞서, 우리가 요약하는 현상이 수집 방식에 얼마나 민감한지 확인하기 위한 질문이다.
10분 관측도 연속 시간의 완전한 정답으로 취급하지 않는다.

후속 실행에서 입력 자료를 재감사하고, 한국 시간 조건부 해석과 공개 입력 해시를 확정해 계획을 동결했다.
H-0001은 평균 절대차 1.24%p로 5%p 초과 가설을 지지하지 않았다.
관측 요약의 비교 결과이며 예측 모델 성능이나 연속 시간의 품절 관측 충분성을 입증하지 않는다.

후속 단계의 질문은 아직 별도 실험 계획으로 확정하지 않았다.
실험으로 구체화할 때마다 새 가설 ID와 Draft PR을 만들고, 동결·실행·판단을 연결한다.

## 8. 아키텍처의 첫 검증 이후

[H-0002](H-0002-architecture-results.md)는 대여소 1,369개·세 시드·7일 시험에서 소형 그래프 CFM의 추가 가치를 지지하지 않았다.
좌표 그래프 직접 예측의 자기 이력 대비 평균 개선은 약 0.93%지만, 보조 불확실성 구간은 0을 포함한다.
API로 학습한 자기 이력 예측의 가중치·성능 순위는 최신 계약의 기준선으로 승계하지 않는다.
다음 단계는 예측 대상·관측 과정·공간 관계·확률 표현을 먼저 검토하고,
계수형 예측, 과정 기반 모형, 결합 시나리오 생성이라는 큰 연구 방향을 문헌·자료 조건에 따라 좁히는 것이다.
기존 대중교통·날씨·서울 전이·대형 구조·재배치 정책까지 검증한 것은 아니다.
사용자의 최신 지시에 따라 후속 연구·학습·분석 연산은 dislab에서 수행한다.

## 9. 자료의 확률 구조에서 다시 좁히기

[H-0003](H-0003-results.md)은 기존 개발 기간에서 현재 상태에 조건부인 미래 재고의 변동을 진단했다.
30분 분산/평균 비율의 대여소 중앙값은 0.449로 사전 기준 0.8 미만 가설을 지지했다.
현재 0대가 30분 뒤에도 0대인 비율은 약 87%였으며, 시간 범위와 대여소별 차이도 확인했다.

이 결과는 기존 API 탐색 기록으로 남긴다. 최신 계약에서는 과거 대여이력의 정답·누락·시간 구조를 먼저 감사하고,
그 자료만을 학습·내부 검증에 사용한다. API 통계로 분포나 아키텍처를 고르지 않는다.
GCN·포아송·Flow Matching의 조합이나 최종 네트워크는 아직 선정하지 않았다.
다음 모형 비교는 [연구 프로그램](research-program.md)의 순서와 새 가설의 사전 동결을 따른다.

## 10. 다운로드 이력의 보조 거래 모델 학습

[H-0004](H-0004-results.md)는 과거 대여·반납 원본만으로 고정 평균과 요일×시각 평활 평균을 학습했다.
학습 대여소는 1,192개이며, 평활 강도는 과거 2월에서 선택하고 3월을 내부 보류로 비교했다.
달력 평균은 고정 평균보다 평균 Poisson deviance를 11.35% 줄여 사전 기준을 충족했다.
두 모델을 dislab에 저장하고 재로딩을 확인했다. 채택 범위는 기록 건수의 보조 평균 기준선이다.
API 학습·튜닝·선택·재고 외부 검증을 수행한 결과가 아니며, 최종 공간·생성 아키텍처는 미정이다.
2·3월의 재고 정답을 얻은 것이 아니며 공식 재고 평가 기간도 아니다.
다음은 과거 흐름 학습과 미래 상태 예측을 연결할 가정·검증 입력을 정하고, 9월 API 평가 가설을 동결하는 것이다.
