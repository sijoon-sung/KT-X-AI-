# 공모전 발표와 현장 도입 계획

## 프로젝트 소개

**타슈가 필요한 곳에 자전거를 먼저 채우도록 돕는 운영 도우미다.**

시민은 대여소까지 갔는데 자전거가 없으면 다시 걸어야 한다. 운영자는 한정된 차량과 시간으로 어느 대여소부터 채울지 정해야 한다. 이 프로젝트는 10분 후 재고를 예측하고, 차량 조건에 맞는 이동 수량과 방문 순서를 제안한다. 작은 언어 모델은 계산된 내용을 짧은 한국어로 설명한다. 배차 담당자가 최종 결정한다.

## 심사 항목에 맞춘 구성

| 항목 | 발표에서 전달할 내용 | 보여줄 근거 |
|---|---|---|
| 주제 적절성 25점 | 대전의 공공자전거 부족과 재배치 업무를 해결한다. 주력 제조업과 억지로 연결하지 않고 생활교통·사회 문제로 제안한다. | 대전시 운영 개선 발표, 이용자 상황, 도입 대상과 실제 사용자 구분 |
| AI 구현 적합성 25점 | 주변 대여소 흐름을 읽고 여러 미래 재고를 예상해 수량·동선 계산에 연결한다. | 고정 H13 예측 출력, 기록 기반 계획, 실제 Qwen 질의응답 화면 |
| 실현가능성 25점 | 기존 운영에 관리자 웹을 붙이고, 1개 권역·1대 차량부터 담당자와 시험한다. | 자원 조건, 자료 갱신·실패 처리, 4주 시범 운영안, 책임자·비용 항목 |
| 파급효과 25점 | 시민의 이용 불편과 운영자의 불필요한 이동을 줄이는 것이 목표다. | 빈 대여소 관측 비율·거리·시간의 측정 방법, 환승 거점과 다른 도시 적용 조건 |

위 표는 평가 대응 계획이며 예상 점수나 수상 가능성을 뜻하지 않는다.

## 지역 문제의 근거

대전시는 타슈 확대와 가동률 개선을 발표했고, 반납·재배치 민원 해소를 위한 인력 충원 계획도 설명했다. 대전교통공사의 사전정보공표에는 타슈 운영 현황과 담당 타슈운영팀이 명시돼 있다. 도입 제안 대상은 대전시와 대전교통공사 운영 부서다. 현재 협약이나 계약은 없다.

- [대전시: 타슈 가동률 개선 발표](https://www.daejeon.go.kr/drh/board/boardNormalView.do?boardId=normal_0189&menuSeq=1632&ntatcSeq=1447807033&recordCountPerPage=10&searchCondition=&searchKeyword=)
- [대전시: 타슈 확대와 반납·재배치 민원 대응](https://daejeon.go.kr/drh/drhStoryDaejeonView.do?boardId=blog_0001&menuSeq=&ntatcSeq=1457244726&pageIndex=1)
- [대전교통공사: 사전정보공표](https://www.djtc.kr/kor/board.do?menuIdx=278)

확인일은 2026-11-10이다. 시의 2024년 발표에 적힌 2026년 자전거·대여소 수는 목표이며 현재 운영 규모로 인용하지 않는다. 특정 대여소에서 몇 명이 자전거를 못 빌렸는지는 API 재고만으로 알 수 없다.

## 구현 범위와 기술의 역할

| 구성 | 역할 | 현재 상태 |
|---|---|---|
| H13 GCN | 연결된 대여소의 과거 흐름을 표현한다. | 고정 모델. XGBoost보다 항상 좋다는 주장은 하지 않는다. |
| 포아송 rate head | 대여·반납 건수의 조건부 평균·기준 분포를 제공한다. | 과거 거래로 학습. API로 보정하지 않는다. |
| 조건부 Flow Matching | Gaussian 출발 잔차 경로로 여러 미래 대여·반납을 표집해 재고 분포를 계산한다. | H13 원 가중치 유지. 포아송 출발 H24와 구분한다. |
| 재배치 계획 | 차량 적재, 방문 수, 출발 거점, 작업 시간 안에서 수량·동선을 계산한다. | 기록 기반 시제품. 도시 전체 최적이나 실제 절감 실증은 아니다. |
| Qwen3-1.7B | 이미 계산한 예측·계획을 쉬운 말로 설명한다. | dislab GPU 실제 추론. 근거 확인 실패 시 자료 문장으로 표시한다. |

LLM은 예측 입력을 늘리거나 배차를 실행하지 않는다. 학습은 과거 거래 기록, 공식 재고 평가는 9월 API로 분리한다. 새로운 운영 관측을 추론에 쓰더라도 가중치·분포·임계값 선택에는 쓰지 않는다.

## 발표에 쓸 성능

9월 1,298개 지원 대여소의 2,458,501쌍에서 현재 재고 유지와 비교했다. 자료는 이미 노출된 공식 평가 자료이며 독립 미열람 시험으로 부르지 않는다.

| 방법 | 예측분포 오차 fairCRPS ↓ | 대수 중앙값 MAE ↓ |
|---|---:|---:|
| 현재 재고 유지 | 0.212015 | 0.212015대 |
| GCN·최근 입력·포아송 | 0.179170 | 0.212039대 |
| GCN·최근 입력·Flow Matching | 0.179756 | 0.211982대 |

발표 문장: **“현재 재고를 그대로 유지하는 예측보다 예측분포 오차가 15.22% 감소했습니다.”** 확률분포 전체의 오차를 말하며 정확도 15.22% 향상이라는 뜻은 아니다. 대수 MAE는 거의 같다. FM이 포아송보다 더 좋다는 결과도 얻지 못했다. 근거는 [H13 결과](H-0013-rolling-api-flow.md)다.

재배치 후 품절 감소율, 실제 미충족 인원, 절감액은 아직 측정하지 않았다. 예전 기획 수치인 정확도 35.7% 향상·품절 65% 감소는 사용하지 않는다.

## 시연 순서: 약 90초

1. 기록 시각을 보여주고, 실제 수집 기록을 재생하는 화면임을 설명한다.
2. 부족 예상 대여소와 공급 후보를 고르고 차량 적재·시간 조건에 맞춘 계획을 보여준다.
3. 대여소별 싣기·내려놓기 대수, 방문 순서, 예상 거리·시간을 확인한다. 표시 거리는 계획 추정값이다.
4. 도우미에게 “총 몇 대를 옮겨?”, “어떤 순서로 가면 돼?”라고 묻는다. 답변과 원래 계획의 값을 비교한다.
5. “실제로 못 빌린 사람은 몇 명이야?”에는 알 수 없다고 답하는지 보여준다.

기록 재생과 합성 설치 예시는 각각 표시한다. 현재 스트림을 수신하지 않으면 실시간 시연이라고 말하지 않는다. 재배치 지도와 질문 화면의 기록 시각·계획 버전이 다르면 한 계획으로 묶어 설명하지 않는다. 통신 장애 시에는 마지막 기록과 원래 계획표를 보여주고 새 권고 발행을 멈춘다.

## 4주 시범 운영 제안

범위는 1개 권역·1대 차량이다. 실제 적재량·거점·근무 시간·도로 조건을 담당자와 확인한 뒤 계획 예산을 확정한다. 이 일정은 제안이며 확정된 현장 실험이 아니다.

| 단계 | 수행 내용 | 책임 제안·산출물 |
|---|---|---|
| 1주차 | 자료 권한·관측 지연·대여소 지원 범위 확인, 차량·상하차·주차 조건 조사 | 운영기관 담당자와 개발팀 / 조건표·기준 운영 로그 |
| 2주차 | 실제 작업은 유지하고 같은 시점에 모델 계획만 생성 | 개발팀 / 계획 버전·추정 거리·제약 위반·소요시간 |
| 3주차 | 운영자가 검토한 계획을 한정 적용, 거절 이유와 변경 수량 기록 | 배차 담당자·기사 / 승인·실제 도착·수량·주행 기록 |
| 4주차 | 비슷한 요일·시간·기상 조건의 기존 운영과 비교, 장애·사용자 의견 검토 | 운영기관·개발팀 / 효과·비용·보완 과제 보고 |

계절·시간·행사·다른 차량의 개입이 효과에 섞이므로 단순 전후 차이를 인과 효과로 확정하지 않는다. 현장 승인 전 별도 비교 계획을 동결한다. 지역 전체 평균만 보지 않고 권역·출퇴근 시간대·현재 0대/양수 그룹을 함께 확인한다.

## 효과와 비용을 확인하는 방법

| 지표 | 정의·수집 | 해석 |
|---|---|---|
| 빈 대여소 관측 비율 | 유효 재고 관측 중 0대인 관측 수 / 전체 유효 관측 수 | 관측 사이의 연속 품절 시간이나 포기 인원으로 바꾸지 않는다. 누락을 0으로 채우지 않는다. |
| 현재 양수→10분 후 0대 | 유효한 연속 두 관측에서 전환 비율·미탐률 | 이미 0대인 대여소와 별도 보고. 모델 점수와 현장 결과를 구분한다. |
| 이동 거리·작업 시간 | 실제 주행·도착·상하차 기록, 운반 대수도 함께 기록 | 추정 경로와 실측을 비교한다. 덜 옮긴 결과만으로 효율 개선을 선언하지 않는다. |
| 계획 작성 시간·채택률 | 담당자 화면 사용 시간과 승인/수정/거절 사유 | 사용성·업무 부담 확인. LLM 답변 수와 운영 성과는 별개다. |
| 제약 위반·갱신 지연 | 적재 초과·음수 재고·오래된 자료·권고 발행 시각 | 자료가 오래되거나 누락되면 추천 중단 또는 보류 표시 |

월간 편익 추정식은 `(기존 대비 실제 주행 km 감소 × km당 비용) + (실제 작업 시간 감소 × 시간당 비용)`이다. 작업 시간 인건비에 차량 운행비를 이미 넣었다면 중복 합산하지 않는다. 비용 단가와 차이를 측정하기 전 금액을 제시하지 않는다.

사업 형태는 기관별 초기 연동·설정비와 유지관리비를 받는 구축형 제안이다. 권한 있는 공개·운영 데이터 연동, GPU 서버·보안·관측 모니터링, 장애 대응 인력, 지도·경로 이용 조건을 견적에 포함한다. 현재 매출·고객 계약·도입 의향서는 없다.

## 다른 교통과 연결하는 예시

도시철도 환승역 근처 대여소를 묶어 출퇴근 시간대의 공급 계획을 비교하는 시범안을 제안한다. 버스·도시철도 도착·이용 현황은 우선 운영 화면에 겹쳐 보여주고 담당자가 상황을 확인하는 보조 자료로 쓴다. 현재 확정 모델의 입력 특징은 늘리지 않는다. 모델 통합이 필요해지면 시각 정렬·사용 권한·미래 정보 유출을 확인한 별도 연구로 진행한다.

다른 도시의 공유자전거에는 대여소 번호·시각·대수·작업 로그의 공통 형식을 적용할 수 있다. 운영 규칙·계절·규모가 달라 해당 도시 자료로 재학습·검증해야 한다. 킥보드까지 확장하려면 주차 구역·회수 비용·법규가 달라 별도 운영 문제로 다룬다.

## 5분 발표 흐름

- 0:00~0:45: 자전거가 없는 대여소를 만난 시민과, 한정된 차량으로 움직이는 운영자의 문제를 설명한다.
- 0:45~1:30: “10분 뒤 부족할 곳을 예상해 수량과 동선을 정한다”는 해결 방법을 보여준다. GCN·포아송·FM은 각 한 문장만 설명한다.
- 1:30~3:00: 기록 기반 계획과 질문응답을 실제 화면에서 시연한다.
- 3:00~3:40: 9월 평가 표를 보여준다. 15.22%는 예측분포 오차 감소이고, 대수 오차는 거의 같다고 설명한다.
- 3:40~5:00: 4주 시범 운영, 측정 지표, 기관 도입 방식과 환승 거점 확장안을 설명한다.

질문 답변: “왜 XGBoost 대신 GCN인가요?”에는 “대여소 사이의 연결을 표현하려고 사용했습니다. 모든 비교에서 더 좋다는 근거는 없습니다”라고 답한다. “왜 LLM인가요?”에는 “예측 결과를 바꾸는 용도가 아니라 담당자가 수량·순서를 쉽게 확인하도록 붙였습니다”라고 답한다.
