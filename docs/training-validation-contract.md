# 과거 이력 학습 · API 검증 전용 자료 계약

기준일: 2026-10-31. 사용자의 최신 지시가 이전 API 개발 실험의 자료 사용 방식보다 우선한다.
여기서 API는 타슈 재고 API 수집 자료를 가리킨다.
공식 재고·품절 평가는 [9월 API 평가 계약](september-evaluation-contract.md)에 따라 **2026년 9월**에 고정한다.
2·3월 다운로드 기록에는 거래 건수만 있고 실측 재고 정답은 없다. 그 기간의 건수 비교는 보조 진단이다.

## 1. 가설

후속 모델은 **기존 과거 기록에서 학습하고 API 관측은 외부 검증에만 사용**한다.
이는 연구의 자료 사용 원칙이다. 새 모형의 우월성 가설이나 검증 성공 결과는 아직 아니다.
모형군은 과거 이력의 관측 대상·품질·시간 구조와 선행연구를 근거로 좁힌다.

- 과거 대여·반납의 실현된 거래, API 표시 재고, 잠재 수요를 구분한다.
- 과거 코드의 아이디어는 참고하지만 과거 점수나 가중치를 새로 재현한 증거로 승계하지 않는다.
- API에서 본 성능·분산·0 비율을 근거로 새 분포·구조·임계값을 선택하지 않는다.

## 2. 실험

### 자료별 역할

| 자료 | 허용 역할 | 후속 학습·선택에서 제외할 사용 |
|---|---|---|
| 과거 대여이력 원본 | 학습, 과거 기간 안의 시간 순서 검증·모형 선택·보정 | 미래 거래를 과거 특성·OD·운영 여부·복원 재고에 사용하는 것 |
| 과거의 실측 재고·운영 로그 | 원본·시각·출처를 확인한 경우 해당 정답·상태의 후보 | 거래로 복원한 값을 실측 정답으로 바꾸는 것 |
| 9월 API 수집본 | 모델·전처리·출력·평가 규칙을 고정한 뒤 공식 재고·0대 관측 평가 | 가중치 학습·미세조정·조기 종료·구조/분포/하이퍼파라미터 선택·확률 보정·경보 기준 선택 |
| API에서 파생한 통계·특성 | 사전 정의한 검증 표본의 대응·시차·누락 보고 | 학습용 정규화·그래프·대여소 선택·평균 패턴·학습 입력으로 재사용 |
| 기존 API 학습 모델·캐시 | 과거 실행 기록으로 보존 | 새 모델의 초기 가중치·학습 특성·선택 근거로 승계 |

API 수집본은 검증 단계로 분리한다. 검증 시작 상태·검증 입력·미래 정답의 구분은
후속 평가 계획에서 명시하고, 미래 정답을 초기 상태나 입력으로 사용하는 누출을 막는다.
이번 출처 확인 작업에서는 API를 검증 입력으로도 사용하지 않았다.
API와 대여소 ID·시각을 맞추는 작업은 검증 단계의 대응표이지 학습 대여소 선택 규칙이 아니다.
학습 대상 집합은 과거 자료만으로 고정하고, API와 매칭되지 않는 대상도 제외 내역으로 보고한다.

### 확인한 과거 원본과 아직 남은 감사

dislab에서 `대전교통공사_대전시 공영자전거 타슈 대여이력 정보_20260331.zip`을 확인했다.
원본 ZIP은 493,887,524바이트, SHA-256은
`b43e78c373050d0aae2208db037538187066c565b7d5833f462b2ea94d42560b`이다.
월 이름상 2024-08~2026-03의 CSV 20개이며, 실제 행의 날짜·누락·중복·월 불일치는 별도 감사 대상이다.
확인한 열에는 대여/반납 시각·대여소 ID·좌표와 자전거 번호가 있다. 실측 재고 열은 확인하지 못했다.
원본 개인 경로와 개별 거래·자전거 ID는 공개하지 않는다.

ZIP 내부 파일의 인코딩·해시·열·행 수·파일 월과 대여 월을 dislab에서 감사했다.
실제 대여 날짜 범위는 2024-08-01~2026-03-31이며 원본 9,320,018행이다. 유효 학습 표본 수는 아직 아니다.
파일별 인코딩은 cp949 9개·UTF-8 계열 11개다. 2025-12 이름의 파일 203,545행은 대여 월이 2025-01이었다.
상세 근거는 [원본 감사](historical-source-audit.md)와 [공개 원본 목록](sources/tashu-historical-trips-source-v1.json)에 기록한다.
기존 전처리에서 알려진 2025-12 파일의 월 불일치, 장애 기간, 미래 반납을 이용한 재고 복원 문제를
확인 전 정상 자료로 간주하지 않는다. 거래가 없는 시간과 기록이 누락된 시간을 같은 0으로 만들지 않는다.

### 다음 학습과 검증 순서

1. 과거 원본의 실제 기간·열·누락·중복·대여소 변경을 감사하고 학습 입력 목록과 해시를 고정한다.
2. 과거 자료 안에서 시간 순서 학습·내부 검증을 정한다. 학습 구간만으로 그래프·정규화·대여소 특성을 만든다.
3. 학습 정답과 외부 평가 대상의 연결을 정한다. 대여/반납 건수는 API 재고와 같은 변수가 아니다.
4. 새 가설 ID·Draft PR에 비교군·학습 예산·지표·판정 기준을 동결한 뒤 dislab에서 학습한다.
5. 과거 내부 검증으로 선택을 끝내고 가중치·입력 생성·시드·평가 규칙을 고정한다.
6. 그 뒤 **9월 API**를 공식 재고 평가에만 연다. 결과가 나빠도 같은 API에 맞춰 재학습·구조 선택·보정을 반복하지 않는다.

거래 순흐름에서 재고 변화를 예측하려면 운영자 이동·상태 보정과 초기 상태를 다루는 가정이 필요하다.
거래 기록의 재고 하한 복원은 추정값이지 API와 동일한 정답이 아니다.
과거에 실측 재고가 없으면 거래 예측의 성능과 API 재고 예측의 성능을 각각 구분하고,
연결이 성립하기 전에는 “API로 검증된 재고 모델”이라고 부르지 않는다.

## 3. 결과

### 기존 실행의 현재 위치

| 기록 | 실제 수행 내용 | 최신 계약에서의 위치 |
|---|---|---|
| H-0001 | API 관측 간격별 0대 요약 비교 | 기존에 수행한 API 자료 감사 기록. 새 모델 학습·선택의 근거로 사용하지 않음 |
| H-0002 | API 재고를 학습·검증·시험으로 나눈 소형 모형 비교 | **최신 자료 계약 밖의 과거 실험.** 과거 이력 학습→API 검증을 수행한 결과가 아님. 가중치·성능 순위를 승계하지 않음 |
| H-0003 | API 개발 기간의 조건부 변동 탐색 | **이미 검증 자료를 탐색한 과거 진단.** 새 모형의 분포·아키텍처 선택 근거에서 제외 |

동결한 계획·수치·실패 기록은 사실대로 보존한다. 과거 실행을 소급해서 계약 준수 실험으로 바꾸지 않는다.
H-0003의 0.449라는 수치가 삭제되는 것은 아니며, 후속 학습 자료에서 얻은 증거로 쓰지 않는다는 뜻이다.

### 검증 자료의 노출과 다음 행동

기존 2026-09-17~10-30 API는 이미 요약·학습·시험·구조 탐색에 사용됐다.
지금부터 검증 전용으로 분리하더라도 **아무도 보지 않은 독립 시험 자료**가 되지는 않는다.
공식 평가는 그중 **9월 수집분**으로 고정하고 이미 열람한 평가 자료임을 명시한다.
새 API 기간은 별도 추가 검증 후보일 뿐이며 공식 9월 평가를 대체하거나 진행 조건이 되지 않는다.

후속 [H-0004](H-0004-results.md)는 이 과거 이력만으로 두 평균 건수 모델의 보조 학습·내부 비교를 완료했다.
이 2·3월 분할은 재고 평가 기간이 아니다. 다운로드 기록은 학습 범위이고 실측 재고 정답은 9월 API에서만 평가한다.
다음 행동은 학습한 흐름을 미래 재고 상태에 연결할 가정과 공식 9월 평가 계획을 새 가설로 정하는 것이다.
GCN·포아송·Flow Matching은 이 과거 자료의 정답과 구조에 맞춰 다시 검토한다.
이번 자료 계약 변경 자체로 새 모델을 학습했거나 API 검증을 통과했다고 주장하지 않는다.
