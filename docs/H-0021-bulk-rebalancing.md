# H-0021 · 한 번 방문할 때 여러 대를 수거·배치

## 가설

기존 기본값 적재6대·이동6대·목표2대·대여소당 추가3대는 작은 시연 규모였다. 사용자 요청에 따라 적재20대·이동20대·목표6대·추가주차10대·상하차20초/대의 운영 가정을 설정할 수 있게 한다. 실제 타슈 자원 확인값이 아니며 큰 숫자를 그대로 권고 수량으로 출력하지 않는다.

## 실험

사전 계획 게시 후 dislab CPU에서72개 합성 조건의 수량·차량 적재·공급지 보호·추가주차·상하차·복귀를 검사한다. 10분 예측 유효시간과 출발시각을 유지한다. 현재 API와 고정 예측은 계획 입력이며 학습·튜닝·분포/임계값 선택을 하지 않는다. 비교는 운영 가정을 바꾼 사례로서 같은 자원에서의 알고리즘 우월성이나 실제 운영 절감으로 해석하지 않는다.

## 결과

판정 `supported`는 기능·제약 검사에 한정한다. dislab CPU의72조건 전부 수량 보존·중간 적재·공급지 보호·추가주차·상하차·복귀를 지켰다. 위반0건·합성 조건 최대1회 배치6대다. 화면 전송 회귀7개도 통과했다.

실제18:40관측의 고정 예측을 사용한 관측시점 참고 재생에서는 소규모 설정 총3대, 묶음 설정 총6대였다. 목표 재고와 자원 가정을 바꾼 비교이므로 동일 자원의 알고리즘 개선이나 운영 절감률로 해석하지 않는다.

별도 실제현재시점 RPC는18:40:36에총6대 이동·4.288km·작업포함8.69분 복귀 계획을 발행했다. 수거4+1+1대, 배치1+1+1+3대, 최고적재5대/마지막0대다. 실제 한 대여소에6대를 배치한 결과가 아니다. 출발 시점이 늦어지면 남은 시간과 가능한 수량도 줄어든다. 재배치 실행·현장 효과는 관측하지 않았다.

기본값은 적재20대·이동한도20대·목표재고6대·추가주차한도10대·상하차20초/대이며 화면에서 바꾼다. 실제 차량·주차·작업 측정값이 아닌 운영 가정이다. 10분 예측 이후로 경로를 연장하지 않는다. 더 큰 시간 범위의 운영은 별도30/60분 예측 검증이 필요하다. 후보29곳/최대8회 방문의 제한 탐색이며 도시 전체 최적을 보장하지 않는다.

오래된 관측409 자동 복구는 [PR29](https://github.com/sijoon-sung/KT-X-AI-/pull/29)의 별도 유지보수다. 실제 HTML의 기본 설정을 읽어 최신 표시자료→계획 API를 연결하는 검사에서도 HTTP200과 제약위반0을 확인했다. 화면 자동조작은 브라우저주소를 확인하지 못해 Computer Use 안전 검사에서 중단됐으며 시각검증 통과로 기록하지 않는다.
