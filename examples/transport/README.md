# 교통 연계 예시

가상 버스 도착·도시철도 승하차·도로 속도 자료를 사용한 실행 예시다. 대전에서 관측한 교통량이나 현재 모델의 새 성능 결과가 아니다.

계산 서버에서:

```powershell
python examples/transport/example.py --out private/transport-example.json
```

발행 시각은 2026-11-02 18:00 KST다.

| 입력 | 대여소에 대응한 특성 |
|---|---|
| 정류소 BUS-A의 버스 도착예정 120초 | A의 버스 ETA 120초, 도보 접근 180초 |
| METRO-A의 전날 같은 시간 하차량 1,200명, 당일 15시에 공개 | A의 전날 같은 시간대 하차량 1,200명 |
| BUS-B 정보가 18:02에 공개·수신 | 18:00 입력에서 제외, B의 버스 특성은 null과 present=false |

이 특성은 새 모델의 입력 후보다. 현재 H13의 54차원 기상 입력이나 164차원 자기 입력에 덧붙이지 않는다. 새 교통 특성을 쓰려면 과거 자료로 재학습·선택한 모델이 필요하다. ETA나 하차 인원으로 자전거 대여량을 임의로 늘리지 않는다.

경로 예시는 같은 3대 공급량·차량 조건을 유지한다. S에서 3대를 싣고 A에 2대, B에 1대를 놓고 S로 돌아온다. 적재 4대, 대당 수거·배치 각각 20초, 전체 10분 제한을 가정했다.

- 기본 이동시간: `S→A→B→S`, 2.8km, 작업 포함 7.0분.
- S→A의 1km 구간 속도를 30→10km/h로 입력: 기존 순서가 작업 포함 11.0분으로 마감을 넘는다.
- 같은 공급량에서 `S→B→A→S`는 3.0km, 작업 포함 7.5분으로 10분 안에 복귀한다.

두 순서를 완전 탐색하는 작은 예시다. 도시 전체 경로 최적화나 현장 절감을 입증한 결과가 아니다. 입력과 계산식은 `fixture.json`, `example.py`, 실행 산출물은 `result.json`에서 확인한다.
