# 교통 연계 설계 — 2026-11-02

## 가설

설계 목적: 자전거의 10분 후 재고 예측과 재배치 차량의 경로 비용을 다른 교통 정보에 연결할 수 있게 한다. **문서·인터페이스 설계이며 모형 개선 실험·실시간 연결은 미실행이다.** 포아송과 FM은 현재 비교 경로로 유지한다. 기존 H13 입력·가중치·동결 계획은 변경하지 않는다.

## 실험

### 1. 수요 맥락과 차량 비용을 분리

| 채널 | 입력 후보 | 공간 대응 | 사용 지점 | 현재 확인 상태 |
|---|---|---|---|---|
| 버스 | 정류소·노선, 현재 발표된 도착예정시간·배차간격 | 대여소↔정류소 도보 연결 | 새 과거 거래 예측 모델의 맥락 후보 | 공식 교통공사 포털이 정류소·도착정보 활용을 안내. 실제 인증·과거 보존·수신 미연결 |
| 도시철도 | 역별 과거 시간대 승·하차량, 운행 일정 | 대여소↔역 출입구 도보 연결 | 과거 패턴·환승 맥락 후보 | 과거 공식 공지의 제공 항목 확인. 현재 데이터셋 버전·원본 확보·제공 지연 미확인 |
| 도로 | 링크별 속도·통행시간·폐쇄 | 트럭 경로의 도로 링크 | 시간 의존 경로 비용·진입 가능성 | 대전 가용 링크·허가·라이선스·실시간 수신 미확인. 현재 OSRM 추정 유지 |
| 기상 | 당시 이용 가능했던 관측·예보 발행본 | 관측소↔대여소 / 공간 대표성 | 새 예측 모델의 맥락 후보 | 기존 관측 아카이브·결측 마스크 사용. 전 항목 실시간 수신 미완료 |

버스 ETA는 승객 수가 아니다. 과거 시간대 승하차량은 실시간 승객 수가 아니다. 서울 기록은 표현 사전학습 자료이지 대전의 실시간 환승량이 아니다. 도로 속도를 그대로 자전거 수요로 바꾸지 않는다.

### 2. 공통 이벤트 계약

기계 판독 형식은 [transport-event.schema.json](transport-event.schema.json). 인증값·개인 이동 궤적은 포함하지 않는다.

`source_id, source_version, entity_id, kind, observed_at, published_at, received_at, window_start, window_end, value, unit, quality, purpose`를 보존한다. 시각은 UTC RFC3339, 단위는 필드별 고정한다. 스키마는 필드·타입만 검사하며 아래 시각의 대소 비교는 후속 어댑터에서 별도로 검사해야 한다.

- `observed_at`: 현상 또는 예측 발행의 기준 시각. ETA는 이때 발표된 추정값이며 미래 실제 도착 정답이 아니다.
- `published_at`: 그 버전이 공급자에게서 공개된 시각. **알 수 없으면 null**. 공개 시각을 임의로 과거로 설정하지 않는다.
- `received_at`: 수집기가 해당 버전을 수신한 시각. 추후 정정본은 별도 버전으로 저장한다.
- `window_start/end`: 집계 구간. 예: 승하차 집계는 해당 구간이 끝난 뒤 제공된다.
- `quality`: observed / missing / stale / unavailable. 관측값이 없으면 `value=null`이며 0을 채우지 않는다. 실제 관측 0은 observed와 value=0으로 표현한다.
- `purpose`: demand_context 또는 routing_cost. 도로 비용만 바꾼 사례를 예측 정확도 개선으로 보고하지 않는다.

### 3. 발행 시점 정합 규칙

예측 발행 시각 T에 대해 `observed_at ≤ T`, `published_at ≤ T`, `received_at ≤ T`를 모두 만족하는 버전만 운영 입력에 쓴다. 실제 집계인 경우 `window_end ≤ T`도 요구한다. published_at 불명은 실시간 가용 근거에서 제외한다. 미래 ETA 값은 **과거에 발행된 예측 정보**로 입력 가능하되 미래 실측으로 대체하지 않는다.

입력 신선도 한도·시차·도보 연결·후보 특성은 자료 설명과 과거 내부 검증으로만 정하고 새 실험 계획에 동결한다. 재고 API에서 임계값·가중치·그래프·보정·정규화·모형을 선택하지 않는다. 과거 제공 시각이 없는 아카이브는 인과적 실시간 재현이라고 부르지 않는다. 필요한 경우 정적 과거 패턴으로 제한한 별도 질문을 세운다.

### 4. 관계와 모델 인터페이스

```text
출처별 읽기 어댑터
  → 표준 이벤트·버전 저장
  → 시각/단위/결측/신선도 검사
  → 버전 고정 공간 매핑
      ├─ 과거 자전거 OD 그래프 A_od
      ├─ 도보 접근 관계 A_walk
      └─ 버스/철도 노선 관계 A_transit
  → 대여소별 맥락·마스크·입력 출처 기록
      ├─ 후보 GCN의 관계별 표현 → 포아송 평균 / 조건부 FM
      └─ XGBoost에 같은 관계 집계·달력·기상 제공

도로 링크 이벤트 → 차량 진입/링크 시간 → 경로 비용 행렬
고정 미래 재고 표본 + 현재 재고 + 운영 자원 + 경로 비용
  → 수량·중간 적재·상하차·복귀·유효시간을 검사한 계획
```

관계별 표현·게이트·heterogeneous GNN은 후속 설계 선택지다. 기존 구현의 성과로 주장하지 않는다. 새 대여소 임베딩·관계 생성·결측 fallback도 새 모델 계획에 포함한다. 현재 H13은 임의 추가 입력을 받도록 바꾸지 않으며 미지원 특성은 흘려보내지 않는다.

### 5. 비교 설계와 채택 기준

| 분리할 질문 | 비교군 | 정답·측정 | 실행 상태 |
|---|---|---|---|
| 관계 정보와 GCN의 가치 | 자기 특성 XGBoost / +OD 집계 XGBoost / 같은 입력 GCN | 과거 완료 대여·반납 deviance·시간분할·추론 비용. 고정 후 9월 재고 fairCRPS·MAE·Brier | 새 가설·Draft PR·수치 기준 동결 전 미실행 |
| 교통 맥락의 가치 | 동일 모형 ± 과거 시각 정합 교통 맥락 | 같은 거래 정답·기간·대여소·학습 탐색 예산. 선택은 과거에서만 | 미실행 |
| 도로 비용의 가치 | 같은 수량·자원에서 OSRM / 당시 도로 비용 | 실제 주행·상하차·복귀시간과 계획 오차. 운행 결과 로그 확보 필요 | 미실행 |
| FM의 추가 가치 | 같은 조건의 포아송 / FM / 단순 확률 대조 | 과거 분포 점수, 고정 후 재고 분포·0대 점수. 도시 결합 점수는 실제 결합 모델이 있을 때만 | 기존 H13 추가 이득 불지지, 새 실험 미실행 |

공통 원칙: 과거 이력으로 학습·선택·보정, 9월 API는 고정 후 재고 평가. 미래 API 정답은 입력에서 제외한다. 모든 연구·분석·학습 연산은 dislab에서 수행한다. API 기반 무학습 운영 입력과 평가 정답을 분리한다. 효과가 없으면 기존 고정 경로를 유지한다. 이번 문서는 새 실험의 사전등록을 대신하지 않는다.

## 결과

[가상 입력 실행 예시](../transport-example.html)를 추가했다. 버스 ETA와 전날 같은 시간대 도시철도 하차량을 대여소별 입력 후보에 대응하고, 발행 시점 이후 제공된 버스 정보는 제외했다. 같은 3대 공급량에서 도로 혼잡을 반영하면 기존 순서가 11분으로 마감을 넘고, 다른 순서가 7.5분으로 복귀하는 두 경로 예시다. 계산은 dislab에서 수행했고 홈페이지는 저장된 결과를 전환한다. 입력과 코드는 [실행 코드 브랜치](https://github.com/sijoon-sung/KT-X-AI-/tree/maintenance/model-package-quickstart/examples/transport)에 있다. 실제 교통 관측이나 H13의 새 입력·정확도 결과는 아니다.

데이터 입력 계약·역할·공간/시간 대응·비교 대조군까지 설계했다. **실데이터 연계 어댑터, 교통 입력 모델 학습, 새 정확도, 실시간 혼잡 경로, 현장 효과는 모두 미실행**이다. 다음 행동은 공급자의 데이터 버전·이용 조건·과거 보존·제공 시각을 확인한 뒤, 확보된 한 채널의 추가 가치를 새 가설 PR로 동결하는 것이다. 승인된 타슈 키를 다른 교통 서비스의 키로 재사용하지 않는다.

근거 확인일 2026-11-02:

- [대전교통공사 역 주변 교통정보](https://www.djtc.kr/kor/stationTourList.do?area=104&menuCode=2): 활용 데이터 항목의 타슈·TAGO 정류소·대전 정류소별 도착정보 설명 확인. 실 API 호출은 수행하지 않음.
- [대전교통공사 과거 Open API 공지](https://www.djtc.kr/kor/board.do?bbsIdx=2893&menuIdx=361): 역별 시간대별 승하차 항목의 과거 제공 안내 확인. 현재 서비스 유효성은 미확인.
- [GCN 원문](https://arxiv.org/abs/1609.02907): 그래프 구조와 노드 특성의 표현 학습 개요 확인. 타슈/XGBoost 우위 근거가 아님.
- [XGBoost 원문](https://arxiv.org/abs/1603.02754)·[공식 파라미터](https://xgboost.readthedocs.io/en/stable/parameter.html): 트리 부스팅·count:poisson 지원 확인. 그래프 특성 사용을 배제하지 않음.
- [Flow Matching 원문](https://arxiv.org/abs/2210.02747): 확률 경로의 벡터장 회귀 개요 확인. FM의 일반 OT 선택지를 현재 구현의 OT 증거로 쓰지 않음.

공공데이터포털 직접 상세 페이지와 국가 ITS 페이지는 이번 도구에서 조회 실패/시간 초과였다. 엔드포인트·쿼터·대전 커버리지를 확인한 것으로 기록하지 않는다.
