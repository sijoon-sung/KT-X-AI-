# 타슈 발표 가이드 — 5분

발표 범위: **GCN·포아송·Flow Matching으로 10분 후 재고 분포를 예측하고, 수량·동선을 제약 안에서 계획하는 연구 시제품.** 현장 도입·운영 절감 입증 발표가 아니다.

## 발표 흐름

| 홈페이지 | 시간 | 핵심 문장 |
|---|---:|---|
| 첫 화면 | 20초 | 현재 자전거 수를 확인하는 데서 더 나아가, 운영자가 어디에 몇 대를 옮겨야 할지 판단하도록 만들었습니다. |
| 해결한 문제 | 35초 | 0대의 대여 기록 0건은 수요가 없다는 뜻이 아닙니다. 미래 위험과 공급 여유, 도착시간을 연결하되 잠재 수요 정답을 얻었다고 가정하지 않았습니다. |
| 핵심 기술 | 60초 | GCN은 과거 이동으로 연결된 대여소 관계를 표현합니다. 포아송은 대여·반납 횟수의 조건부 평균과 건수 분포를 다루는 기준선입니다. FM은 GCN의 조건 아래 로그 건수 잔차를 생성해 여러 미래 재고 가능성을 제공합니다. |
| GCN 선택 | 35초 | 관계를 학습하는 표현을 확률 출력과 공유하려고 선택했습니다. XGBoost도 이웃 특성과 포아송 목적함수를 쓸 수 있으므로 정확도 우위는 동일 조건 비교 전까지 주장하지 않습니다. |
| 실제 성능 | 60초 | 9월 17~30일 1,298개 대여소, 2,458,501개 예측–관측쌍에서 현재 유지 대비 fairCRPS가 포아송 15.49%, FM 15.22% 낮았습니다. 수량 MAE는 거의 같고 FM의 추가 이득은 확인되지 않았습니다. |
| 재배치 | 40초 | 실제 API 입력에서 총 6대, 4.288km, 작업·복귀 포함 8.69분의 계획을 발행했습니다. 실제 배차가 아니며 운영 자원은 가정입니다. |
| 교통 연계·완료 범위 | 50초 | 버스·철도는 환승 맥락에, 도로 혼잡은 차량 이동시간에 연결하는 구조를 설계했습니다. 다음 단계는 실제 자원·행동 로그와 동일 조건 모델 비교입니다. |

홈페이지 상단 ‘발표 모드’ → ←/→ 또는 PageUp/PageDown, Esc 종료. 화면이 길면 스크롤해 내용을 볼 수 있다. 인쇄 버튼은 브라우저의 인쇄 대화상자를 열며 PDF 파일은 사용자가 저장한다.

## 질문에 대한 답변

**GCN이 XGBoost보다 좋은가?** 관계를 표현하는 방식이 다르다. 동일 조건 직접 비교는 미실행이다. XGBoost+OD 집계 대조군을 두어 정보와 표현의 이득을 분리하는 것이 다음 비교다. 기존 제한된 GCN 비교는 우위를 지지하지 못했다.

**포아송과 FM을 함께 쓰는가?** GCN의 조건 표현을 공유하는 별도 확률 출력·비교 경로다. 현재 결과를 포아송-FM 혼합 앙상블의 성과로 설명하지 않는다. FM을 연구 경로에 포함했지만 포아송보다 우수하다는 증거는 없다.

**MAE 35.7% 감소인가?** 아니다. 현재 확인된 주 수치는 재고 분포 fairCRPS의 현재 유지 대비 감소다. MAE는 현재 유지 0.212015대, 포아송 0.212039대, FM 0.211982대로 거의 같다.

**0대 대여소의 진짜 수요를 아는가?** 아니다. 완료 거래와 표시 재고로 미충족 수요의 정답을 얻을 수 없다. 공급 후보와 위험에 반영하는 단계이며 실제 효과는 행동·결과 로그가 필요하다.

**실제 재배치 효과를 검증했는가?** 계획·제약 검사를 했다. H21 합성 72조건 위반 0은 현장 품절 예방률이 아니다. 실제 6대 계획도 배차를 수행한 결과가 아니다.

**교통량은 이미 입력인가?** 기상 관측 이력은 사용했다. 버스·도시철도·실시간 도로 연계는 문서·스키마 설계 단계다. 미래 통계를 당시 입력으로 오인하지 않도록 제공·수신 시각을 분리한다.

**API로 계속 학습하는가?** 아니다. 과거 거래로 학습·내부 선택하고 고정한 모델이 당시 API를 추론 입력으로 사용한다. 다음 관측은 평가 정답으로 분리한다. API 가중치 갱신·튜닝·보정·모형 선택은 금지한다.

## 발표 직전 실행 확인

1. 홈페이지 `http://127.0.0.1:8771/`를 열어 발표 모드와 글자 크기를 확인한다.
2. 관리자 `http://127.0.0.1:8770/dispatch?mode=bulk`의 실제 관측 시각·예측 만료·서버 연결을 확인한다. 페이지가 열린 것만으로 실시간 수집을 주장하지 않는다.
3. H18 수집은 24시간/요청 상한 시험이다. 완료·만료 상태이면 상시 운영처럼 소개하거나 수집을 무단 재시작하지 않는다. 기록 사례의 관측·발행 시각을 보여주는 방식으로 시연한다.
4. 네트워크·원격 연결이 불가하면 홈페이지의 날짜가 명시된 H13 평가와 H21 계획 사례로 발표한다. 오래된 계획을 현재 출동 지시로 사용하지 않는다.
