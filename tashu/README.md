## 핵심 검증 모델 및 파이프라인

1. **실측 API 품절 예측 (`stockout_head.py`)**: 최근 실시간 API 재고 37개 시간 창에서 품절 AUC **0.816** 달성 (단순 재고량 기준 0.750 대비 우수).
2. **절단 수요 복원 모델 (`demand.py`)**: 재고 고갈(노출도 저하)에 따른 미관측 잠재 수요를 음이항-노출도 모델로 복원 (가상 검증 0.97 복원율).
3. **공간 배분 검증 (`assess_spatial_allocation.py`, `build_train_od.py`)**: OD 그래프를 통한 대여소 간 통행 배분 이득 검증.
4. **미채택 실험 코드 아카이빙 (`archive/legacy_experiments/`)**: 순재고 변화 오차가 크거나 실데이터 검증에 부적합했던 유체/플럭스, ST-GCN 구버전, 강화학습 실험 스크립트 29개 및 체크포인트 54개는 아카이브 폴더로 안전 격리.

대전 타슈 대여이력(ZIP)만으로 대여소×시간 텐서와 **재고·절단(censoring) 표시**를 만든다.
실시간 재고 API 없이, `자전거번호` 궤적으로 재고를 복원한다.

## 재고 복원 규칙

같은 자전거의 연속 이용 (a→c)에서 a 반납 대여소 = c 대여 대여소면 그 사이 그 대여소에 서 있었다 (전체 쌍의 99.1%).
다르면 재배치로 보고 도착 시각을 모르므로 두 가지 경계를 둔다.

- **하한**: 확실한 정차만. 72시간 넘게 서 있으면 이후는 고장/방치로 보고 제외 (`--max-idle-h`).
- **상한**: 방치 절단 없음, 재배치 자전거는 공백 동안 출발·도착 양쪽에 있었다고 봄.

모델 학습의 절단 표시는 **하한(`censored`)을 권장**한다. 절단이 아닌 구간을 절단으로 처리해도
censored likelihood(`P(Y ≥ y_obs)`)는 여전히 참이라 편향이 없고, 정보만 조금 잃는다.
반대로 절단 구간을 놓치면 수요를 과소추정한다.

## 원본 데이터 이슈 (자동 처리됨)

- `25년12월` 파일 내용이 실제로는 **25년 1월 데이터의 중복**이다 → 파일명 월과 다른 행 제거, 25년 12월은 결측 처리.
- `25년03월` 파일은 시각 형식이 다름 (`2025-03-05 7:16`, 초 없음) → 정규화.
- 25-02-26 오후 ~ 25-03-04 오전 시스템 장애 → 마스킹.
- 일부 기간 00–05시 야간 운영중단 → `closed` (재고 연속성은 유지).

## 현재 결과 요약 (60분, 2024-08 ~ 2026-03, 1,425개 대여소, 912만 건)

| 지표 (07–22시) | 하한 재고 기준 | 상한 재고 기준 |
|---|---|---|
| 재고가 한 번이라도 0이 된 대여소·시간 비율 | 65% | 36% |
| 내내 재고 0인 비율 | 41% | 25% |
| 절단 구간에서 발생한 대여 비중 | 50% | 18% |
| 평균 재고 | 1.3대 | 3.2대 |

대여 상위 10% 대여소의 재고 0 비율 중앙값은 8%에 그친다. 재고 부족은 주로 이용이 적은 대여소에 몰려 있다.

같은 자전거를 같은 대여소에 반납하고 3분 안에 다시 빌린 기록(전체의 12%)은 한 이용으로 합친다 (`--merge-min`).
새 손님이 아닌데 '노출 몇 초에 대여 1건'으로 보여 수요를 크게 부풀리기 때문이다.

# 수요 복원 모델 (`demand.py`, GPU)

```bash
.venv\Scripts\python.exe demand.py validate-sim    # 검증 A
.venv\Scripts\python.exe demand.py validate-real   # 검증 B
.venv\Scripts\python.exe demand.py fit             # → data/demand/
```

`.venv` 에는 CUDA torch(2.11+cu128)가 설치돼 있다 (시스템 파이썬의 torch 는 CPU 전용).

모델: `Y ~ NegBin(μ)`, `log μ = H[대여소, 시간대, 주말] + g[시간] + M[대여소, 월]`.
H 는 OD 이동 그래프 위 GNN 으로 대여소 임베딩을 평활해 만든다. 학습 손실은 노출 모델 `y ~ NB(μ·e)` 이다
(재고가 있던 시간 비율 e 동안 온 손님은 모두 빌렸다고 가정). 놓친 수요는 `μ·(1−e)` 이다.

**검증 A — 가상 세계** (재고가 끝까지 남은 셀 = 진짜 수요를 아는 셀에 대여소별 실제 재고 한도로 절단을 시뮬레이션,
관측이 진짜 수요의 55%로 줄어든 상태). 절단된 셀의 실제 수요 복원율은 다음과 같다.

| 방법 | 복원율 | MAE |
|---|---|---|
| 관측 그대로 | 0.43 | 0.64 |
| 규칙: 과거 평균 | 0.56 | 0.61 |
| naive (절단 무시) | 0.60 | 0.60 |
| drop (절단 구간 버림) | 0.58 | 0.57 |
| tobit | 1.01 | 0.59 |
| **exposure (제안)** | **0.97** | **0.53** |

**검증 B — 실데이터 보정** (구간 시작 재고 ≥ 3 인 낮 시간 셀 hold-out, 예측합/실제합; 이 셀의 6.5%는 재고가 소진돼
이상적인 값은 1보다 약간 크다). naive 0.67, drop 0.74, exposure 0.88–0.90, tobit 1.00.
→ exposure 모델의 수요 수준 μ 는 실데이터에서 약 10% 과소일 수 있다
(재고로 잡혔지만 고장 나서 못 빌린 자전거가 있으면 이렇게 된다). 결과는 보수적 추정으로 읽을 것.

**실데이터 추정 (fit, `--exposure lbx`)** — 놓친 수요는 재고가 없던 시간을 재고 하한/상한 중 무엇으로 세느냐에 따라
**전체 수요의 31–48%** (353만–708만 건, 관측 776만 건 대비). 상위 대여소는 충남대 기숙사·도서관, 유성온천역, 갈마역,
시청역 등이다. 재고가 있던 시간이 300시간 미만인 29개 대여소는 `reliable=False` 로 순위 뒤에 둔다.
